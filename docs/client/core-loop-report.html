What the app now shows that Jellyfin hid

Before playback

  • Every version with resolution, HDR, codecs, audio, languages, size, bitrate, age and health
  • How this device will play it (direct, remux, transcode, VLC) and why
  • A start stepper: resolving, fallback with the failed release and the reason, repairing, planning

During and after

  • Errors with the server's suggested actions ("choose another version", "retry", the device holding the stream)
  • Visible step-down notice when a method fails, refused switches keep playing
  • An info panel with method, engine, codecs, HDR, bitrate and dropped frames

Decisions for you

"Recommended" version

The server ranks by quality only, so the web recommends a 4K HDR10 transcode over a 1080p direct stream.

Proposal: recommend the best version that plays without transcoding on this device; transcode only when none exists. This also decides what a plain "Play" starts.

Where the web client is hosted

Served by the Streamarr server (same origin, no CORS) or deployed separately (needs a CORS setting for viewer endpoints).

Proposal: serve it from the server; it is simpler and needs no new setting.

Server URL http://localhost:39300 (Android emulator: http://10.0.2.2:39300). Viewers anna, kind, gast, ben (TOTP), password streamarr. The Codecraft actions devworld, client-web and client-metro start the same things.

How the build ran

Eleven orchestration runs. W2–W10 used the Workflow tool and kept dying with the host session (usage limits, expired tokens, a runner disconnect, and the watchdog's own turns aborting the run). W11 switched to one Codecraft subagent per build, verify or fix step, which survived to the end.
