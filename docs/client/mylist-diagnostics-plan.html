Meine Liste, Speedtest & Server-Diagnose

Branch feat/watchlist-diagnostics auf Basis von origin/main (0.18.0) · Server + Viewer-App (TV/Phone) + Admin-Web

1 · Meine Liste

Will ich sehen→Schaue ich→Aufgeholt (wartet auf Neues)→Gesehen
„Aufgeholt“ springt automatisch zurück auf „Schaue ich“ + Badge NEU, sobald der Monitor eine neue Folge mit brauchbarem Release findet.

Server

  • Neue Tabelle ViewerListEntryEntity (Viewer, WorkId, Art: Film/Serie/Staffel, Quelle manuell/auto, Status, NewAvailableSince, SeenAt) + Migration
  • Auto-Eintrag beim ersten Abspielen einer Episode (Hook in WatchStateService.ReportAsync) – ohne Cutoff/Limit wie bei „Next up“
  • Status wird aus dem Watch-State abgeleitet (Fortschritt x/y Folgen)
  • /api/v1/viewer/list GET/PUT/DELETE, /list/summary (Badge-Zähler), /list/{id}/seen

Verfügbarkeits-Monitor

  • BackgroundService nach Vorbild SpecWarmupService: periodisch, Concurrency-Gate, Tagesbudget
  • Prüft nur Serien, bei denen alle bekannten Folgen gesehen sind: nächste ausgestrahlte Folge(n) laut TMDB
  • „Verfügbar“ = ≥1 nicht abgelehntes, nicht totes Release via GetSeasonReleasesAsync → CatalogSpecStore
  • Backoff: nicht-verfügbare Folgen erneut nach Stunden statt Minuten; Staffelpausen nur täglich
  • Optional Pushover-Event „Neue Folge verfügbar“ (Admin-Ebene)

App (TV + Phone)

  • Neuer Tab Meine Liste mit Abschnitten Neu · Schaue ich · Will ich sehen · Gesehen
  • Badge am Tab (Rail/NativeTabs) mit Anzahl neuer Folgen, Polling via React-Query
  • „Zur Liste“-Button auf Film-, Serien- und Staffel-Details (TV-Stage + Phone-Aktionen)
  • en/de, TV-Fokus-Konventionen, Jest-Tests

2 · Speedtest App ↔ Server

Server

  • GET /viewer/diagnostics/ping (Latenz/Jitter)
  • GET /viewer/diagnostics/speed/download?bytes= – streamt Zufallsbytes, gedeckelt
  • POST …/speed/upload – Ausnahme vom 1-MiB-Body-Limit, eigene Rate-Limit-Policy

App

  • Einstellungen → Verbindung & Diagnose
  • Ping/Jitter, Download (Mbit/s, mehrere Streams, ~8 s), Upload
  • Bewertung: „reicht für 4K HDR / 1080p / nur 720p“ anhand typischer Bitraten
