## Decisions
- Started from `create-expo-app -e with-router-tv` (official SDK 57 TV + Router template),
  stripped the demo. `src/` layout per expo-project-structure; routes only in `src/app`.
- Single Android build: local plugin `plugins/with-android-tv.js` reuses config-tv's Android
  mods on every prebuild; config-tv's `isTV` follows `EXPO_TV` (tvOS). `android` and
  `tv:android` scripts therefore produce identical projects (verified by `diff -r`).
- `npm run ios`/`tv:ios` go through `scripts/prebuild-ios.mjs` (marker `ios/.streamarr-target`,
  `--clean` only when the target changes, `EXPO_NO_GIT_STATUS=1`).
- Dark only: tokens only in `:root`, `colorScheme.set('dark')` in the root layout so RNR's
  `dark:` variants apply on all platforms. Palette taken from `web/src/index.css` (dark) plus a
  `focus` token (white) for the TV focus ring. Brand violet `#6d28d9` for icons.
- TV focus treatment for M2.1: `Platform.isTV && 'border-[3px] border-transparent
  focus:scale-110 focus:border-focus'` in the RNR Button (NativeWind maps `focus:` to
  Pressable onFocus/onBlur). M2.2 replaces this with the real focus primitives.
- Minimal i18n now (PLAN §3 forbids hardcoded strings): `src/i18n` with a dedicated
  `createInstance()`, en/de JSON, key + placeholder parity test. M2.2 owns ICU plurals,
  language override, formatting and the literal-JSX-text check.
- Web `output: "single"` (SPA) to avoid SSR constraints for auth/storage code.
- Gradle limits via `plugins/with-gradle-limits.js` (gradle.properties is generated).
- `gen:api` script present and verified; generated schema left to M2.3.
- `eas.json` from the example removed (EAS/store release out of scope for v1).
- Native permission strings localised via app config `locales` (`locales/native/*.json`).

### Non-blocking
1. `npm run android` / `tv:android` wipe `android/` on every run: SDK 57 `expo prebuild` is
   clean by default (`clean: !args['--no-clean']`), so each run rebuilds natively (measured
   2m41s, 351/475 tasks executed with unchanged sources; ~8 min cold on this machine). Use
   `expo prebuild --platform android --no-clean` in both scripts; README/journal describe it
   as cheap.
2. TV focus ring on the `outline` variant is 1 px, not 3 px: `twMerge` drops the base
   `border-[3px]` in favour of the variant's `border` (checked with `twMerge`; visible in
   `googletv-outline-pressed.png` vs `googletv-focus-primary.png`). M2.2's focus primitives
   must not rely on border width classes that variants override.
3. Multi-line comments break PLAN §3 (one line max): `plugins/with-android-tv.js` (3 lines),
   `scripts/prebuild-ios.mjs` (2), `scripts/render-placeholder-assets.mjs` (2),
   `src/components/ui/icon.tsx` (20-line upstream JSDoc that also names a wrong
   `@/registry/...` import path).
4. Dead dependency `expo-linear-gradient` (never imported; adds a native module). Also
   `expo-glass-effect` / `expo-symbols` are already dependencies of expo-router (fine to keep
   for M2.4). Unused exports: `THEME` has 21 tokens, 6 used; `resources`,
   `SUPPORTED_LANGUAGES`, `detectLanguage` are exported but only used inside `src/i18n`.
5. The raw-hex ESLint rule only matches plain string literals: Tailwind arbitrary values
   (`bg-[#ff0000]`) and template literals get through; consider a class-name check in M2.2.
6. iOS: the base `NSLocalNetworkUsageDescription` in Info.plist is the dev launcher's text; the
   app's own text exists only in `InfoPlist.strings`. Set `ios.infoPlist.NSLocalNetworkUsageDescription`
   in `app.config.ts` so release builds (no dev client) keep the key.
7. `NSAllowsArbitraryLoads` + `usesCleartextTraffic` are global. Intentional for LAN servers;
   M2.3 should warn when a server URL is plain `http` over non-local networks.
8. The i18n "no empty strings" test walks paths via `placeholders()` and re-resolves them;
   works, but a direct leaf walk would be clearer. The literal-JSX-text check from PLAN §3 is
   still missing (M2.2 owns it).
