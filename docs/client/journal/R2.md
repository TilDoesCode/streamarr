# R2 — One large-screen shell (TV, web desktop, tablet)

Status: done

Intent: build the Aurora large-screen shell (glass rail, hero following focus/hover with the ambient backdrop,
rows/cards in mockup sizes with Signal spec labels) once for TV, web desktop and tablet, then search, settings,
profile picker, sign-in/server, tablet and phone compact variants (slice order in runs/driver/R2-notes.md).

## Summary
One large-screen shell (glass rail, hero following focus/hover over the ambient backdrop, 352 × 198 / 208 × 312 cards
with Signal spec chips) renders the same on Google TV and web 1920 × 1080 for Home and Search; Settings, profile
picker, server and sign-in use it too (split layout on every large screen); tablets use it at 1024 px; phones get the
compact variant (stacked hero on the same featured title, Aurora bottom bar). TV back chain, exit dialog, focus/row
memory, deep links and page titles verified after the change. iOS parts are code-only (pending-ios).

## Decisions
- Shell geometry lives in `src/shell/shell-metrics.ts` in 1920 × 1080 mockup points; `useShell().s()` scales them:
  TV = window width / 1920 (Android TV 960 dp → 0.5, exact), web/tablet = max(0.6, width / 1920) so a 1024 px tablet
  stays readable. `large` = every form factor except phone.
- `LargeShell` (navigation/large-shell.tsx) replaces both the TV rail shell and the web sidebar: one glass rail
  (`shell/shell-rail.tsx`), AmbientProvider + AmbientBackdrop behind all tab content, content at x = 104 with a 64 pt
  gutter (104 + 64 = the mockup's 168 left edge). TV keeps the back chain (tvBackAction), exit dialog and screen focus
  host; web keeps fullHistory tabs, `<a href>` items and arrow-key roving. Web phone widths keep the top bar (slice 3).
- Rail labels are per-item overlays shown on focus (TV) or hover (web); nothing shifts. The profile avatar at the
  bottom opens the profile picker on both.
- Home hero: fixed 660 pt area, rows scroll in their own region from y = 648 so the next row peeks. The hero follows
  focus (TV) and hover/keyboard focus (web) through the existing FeaturedStore (delay 250 → 150 ms; the ambient
  backdrop debounces 150 ms on its own). On TV the hero buttons are shown but not focusable (OK on the card plays,
  as before); on the web they are real buttons for the featured title.
- Hero artwork fades into the ambient backdrop through a real alpha mask (`shell/hero-fade.tsx`: nested
  `@react-native-masked-view/masked-view` + expo-linear-gradient; `.web.tsx`: CSS mask-image, intersected), not dark
  scrims: scrims left hard edges over bright ambient art. masked-view was already autolinked in the APK as a transitive
  dependency; it is now a direct dependency (^0.3.2), so no native rebuild was needed.
- Tab navigation inside the shell uses `SHELL_NAV_THEME` (clear scene background) and the tab root screens a clear
  contentStyle, so Search/Settings sit on the ambient backdrop; pushed detail screens keep the opaque background.
- GlassButton and SpecLabel scale with the shell on large screens (64 pt pills / 22 pt text, 15 pt mono chips), so TV
  and web controls have the same proportions.
- Avatar `dimmed` fades only the colour (colour layer at 35 % over surface.raised); the initials stay full white.
- Profile picker: when two servers share a name, the tile caption uses "name · address" (existing
  onboarding.serverChip string).
- Web shortcut: "/" opens Search (ignored in text fields and with modifiers).
- Cards: 352 × 198 landscape / 208 × 312 poster, gap 24, radius 20, caption 22/18, Signal spec chips under the
  caption (3 on landscape, 2 on posters), tint glow on focus. TV poster captions are now always visible (same layout
  as web).

- TV rows (orchestrator decision): Home on TV no longer uses a vertical ScrollView. The rows sit in an Animated.View
  under the hero (paddingTop 648) and are lifted with a translateY (motion.enter): row 0 stays at 648 (lifted only
  by its own overflow), any lower focused row moves to y = 120 (`SHELL.row.focusTop`) with its caption and spec line
  fully visible; rows above the focused one fade out and the hero copy fades out (art dims to 45 %) until focus
  returns to row 0. No native ScrollView auto-scroll fights the JS position. Row focus = the row wrapper's onFocus.
- TV hero buttons: real focusable GlassButtons. A 2 pt full-width TVFocusGuideView above row 0 redirects Up from any
  card to the hero's first button; it unmounts while a hero button is focused, so Down lands on row 0's
  remembering guide (the card it came from). Hero buttons do not set the featured title, so the hero stays put.
  Initial focus is unchanged (first card, hasTVPreferredFocus).
- Remote Play/Pause on Home (card or hero button focused) plays the featured title via the hero's detail query
  (useTVEventHandler in HeroCopy, only while Home is the focused screen).
- `ShellDesign` (shell/shell-design.tsx + theme `DesignScope`): web desktop/tablet screens inside the shell get the
  TV design (type ramp, spacing, control sizes) at `SHELL.width × shell scale`, keeping their own form factor,
  window, focus tokens and gutter. Applied to Search, Settings (route files), the profile picker and AuthScaffold
  (server + all sign-in steps). Result: web Settings/Search/picker are pixel-proportional to TV.
- Web Home keyboard focus: a focused row scrolls so as much of it as fits is visible, bottom (captions) first
  (`revealRow`); the header can be partly under the hero edge for poster rows (row 460 pt > 432 pt region).
- FeaturedStore.lead: the first card of the first row (Continue watching) is the initial hero on web too, so TV and
  web open on the same title; hover/focus (`set`) wins afterwards; `initial` (top pick) is only a fallback.
- Toast: large shell = glass pill (tone-tinted Glass, 44 pt tone disc, 24 pt text); TV shows every toast ≥ 6 s.
- Picker/sign-in: `ShellBrand` (mark + wordmark) top-left on the picker; picker tiles 104 on every large screen.
- Phone compact: stacked hero (4:3.4 art with bottom-only HeroFade, eyebrow, logo/title, meta + cert + spec chips,
  progress, 3-line overview, GlassButtons); greeting bar replaced by brand mark + avatar button (→ /profiles) on
  native; the web phone width keeps WebShell's top bar (it already has the avatar). Android bottom bar: glass.solid
  background, glass.strong indicator pill, white selected tint. iOS keeps NativeTabs Liquid Glass (code only).
- AppTabs (native): LargeShell on every large form factor except Apple TV (Android tablets, iPad); Apple TV keeps the
  native top tab bar (pending-ios).

- Slice 3 decisions:
  - Search grid (large shell): fixed 208 × 312 posters with the 24 pt row gap (Home's size), not stretched columns;
    captions/spec chips come from the same CardCaption (22/18 pt, 2 chips). Phones keep stretched columns.
  - Web keyboard focus on a row below the first: the rows region moves to y = 120 (`SHELL.row.focusTop`), the focused
    row scrolls to its top, rows above fade out and the hero copy collapses (ShellHero `collapsed`) — the TV lift
    geometry. Only `:focus-visible` focus triggers it; mouse/wheel stay free; keyboard focus on row 0 or a wheel back to
    offset 0 restores the hero.
  - AuthScaffold: one split layout (heading left 42 %, form right, high on the screen) for TV and every large web
    width incl. 1024 px tablets; the web back arrow sits above the heading. Phones keep the centred column.
  - Phone hero uses the FeaturedStore too: `lead` (first Continue watching card, eyebrow "Continue watching") on every
    form factor, top pick only as fallback, so Resume never sits under "Trending movies".
  - Large-shell card focus: `useCardScale(width)` caps the focus scale so the scaled card plus ring stays inside the
    24 pt gap (landscape ≈ 1.05, poster ≈ 1.09, phone/handheld keep 1.10); FocusLift got an optional `scale`. Captions
    on the large shell no longer slide on focus: their top padding clears the lifted artwork, so the focused caption
    stays level with its neighbours.
