### 0. iPhone regression: large title + tab bar minimise (I1 verify1 non-blocking 1) — fixed
- Reproduced on the iPhone 18 Pro (iOS 27): Home with its wrapper View never minimised the Liquid Glass bar
  (`04-before-home-scrolled-no-minimise-de.jpg`).
- Root cause, two parts:
  1. UIKit only adopts a scroll view as the content scroll view when it is the screen's first view
     (RNSScreenView > RNSSafeAreaView > RCTScrollViewComponentView > UIScrollView). A wrapper View (Settings since
     I1 slice 6, Home, Search, library pages: View > FocusGuide View) hides it: no minimise, no collapse, no edge effect.
  2. The I1 "title never drawn" was not a re-parenting bug: with the scroll view adopted, iOS 27 moves
     `_UINavigationBarLargeTitleView` into the scroll view (native-find-views: index above the RN content, alpha 1,
     screen y 116) and the navigation bar, opaque from `headerStyle.backgroundColor = colors.background`, covers it.
     The title pixels were exactly the background colour (10,12,18) (`01-before-settings-title-hidden-de.jpg`).
- Fix: the tab roots render the ScrollView/FlatList as the screen's root (testID, background and onLayout moved onto
  it; library keeps FocusGuide only on TV), and the iOS tab-root header gets a clear background
  (`headerStyle: { backgroundColor: colors.scrim.clear }`), so UIKit's scroll-edge effect supplies the legibility.

### A. Resume point lost on start (data loss) — fixed in engine and controller
- Evidence it was real: after slice 3 Sintel was no longer in anna's "Weiterschauen" and its detail showed
  "Erneut ansehen" (the failed 0:00 start had overwritten the 1:36 resume point on the server).
- Engine root cause: `ExpoVideoEngine.load` set `player.currentTime = startPosition` as soon as `replaceAsync`
  resolved, i.e. before the AVPlayerItem was readyToPlay; AVPlayer can drop that seek (seen under load on the
  Direct-Stream HLS remux). The web engine had the same pattern on the native-HLS/progressive path (`video.currentTime`
  set right after `video.src`, before loadedmetadata; Safari can ignore it).
- Fix (engine): new `engines/start-seek.ts` (`StartSeek`): applies the start only when the media is ready, checks the
  time events (lands within 3 s), retries the seek once after 5 events off target, and is cancelled by a viewer seek or
  a new load. `ExpoVideoEngine` applies it on the first readyToPlay (or at once if the item was already ready when
  `replaceAsync` resolved) and defers `play()` until the start seek is issued, so the picture does not run from 0
  first; time events before the seek are not emitted, so the clock shows the start position, not 0:00. The web engine
  applies it on `loadedmetadata` (hls.js keeps its own `startPosition` config). VLC: the start goes in as libVLC's
  media start time (`time` prop) and its time events are already clamped to the start until the clock moves, so no
  change there.
- Fix (controller): `PlaybackController.startFloor` = the attach start position until a time event reaches it (within
  the tolerance) or the viewer seeks (`seekTo`, also replay). While set, every start/progress/stop report is clamped to
  at least the floor, and `resumePosition` (used for switches/step-down) keeps the start instead of a stuck 0-4 s
  clock. A failed start can no longer overwrite the resume point on the server.
- Tests: `controller.test.ts` "resume floor" (start 96 s + engine stuck at 0/2/4 -> start/progress/stop all report 96;
  switch keeps 96; reached 95/97 then 40 -> reports 40; user seek to 10 -> 10; start 0 unchanged) and
  `start-seek.test.ts` (applies only when ready, retries once then gives up, start 0 / cancel do nothing).
- Device (iPad Air 11, AVPlayer): set Sintel to ~1:46 by playing + arrow seeks, Back. "Fortsetzen": remux HLS resumed,
  burned-in clock 00:01:53 after ~7 s (`48-ipadair11-sintel-remux-resume-landed.jpg`). App killed with
  `simctl terminate`, cold start via the dev-client URL, Weiterschauen card: the player clock showed 1:54 while loading
  (no 0:00 flash), picture at 00:01:59. BBB WEB-DL direct play resumed at ~1:52 -> 00:01:58
  (`49-ipadair11-bbb-webdl-direct-resume-landed.jpg`). Sintel again via the Home card at host load 45-65 (the load at

## Decisions
- Start positions are applied by the engine only once the media is ready and verified (StartSeek, retry once); the
  controller never reports below the start until it was reached or the viewer seeked (two independent guards).
- Clock shows the start position while the start seek is pending instead of 0:00.
- iPhone Safari full screen uses the video's native (AVKit) full screen; the custom overlay is not shown there.
- Window-controls (30 pt) and Safari full-screen close (44 pt) insets are constants measured in the iOS 27
  simulator; no native layout-region query.
