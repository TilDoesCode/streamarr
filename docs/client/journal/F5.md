# F5 — Client: switch audio renditions in the players without a new session

Status: done

## Intent
Use the B5 contract (`inSessionAudioSwitch`, `audioRenditions`, `audioTracks[].renditionId`): the audio panel switches
inside the running session (hls.js / Safari audioTracks / AVPlayer / ExoPlayer), `/switch` only when no rendition
exists or the in-session switch fails. Slice 1 (this run): controller decision + fallback, engine track <-> rendition
mapping by language/label, error codes, one consistent audio label, tests, live check on Chrome 1280 with Sintel.
Slice 2: Google TV (ExoPlayer) and Mobile Safari live, the attempt-1 ExoPlayer fix finished, Safari fixes.
Slice 3: iPhone 18 Pro, iPad Pro 13 and Apple TV 4K (AVPlayer media selection via expo-video), remembered language on
Apple, AVPlayer subtitle fixes, wrap-up.

## Summary
The audio panel switches Dev World's dual-audio Sintel inside the running session on web (hls.js), Mobile Safari
(native audioTracks), Google TV (ExoPlayer), iPhone, iPad and Apple TV (AVPlayer): same playbackId and revision, no
source reload, position kept within 0.3 s. In-session switch times: Chrome 62-243 ms, Safari 13-92 ms, iPhone 261-631
ms, iPad 286-548 ms, Apple TV 258-451 ms, Google TV emulator ~1.9 s median (software decode, noisy) - every platform
faster than its `/switch` (Chrome ~1.04 s, Safari 1.1-1.4 s, iPhone 1.2-3.3 s, iPad 2.0-4.4 s, Apple TV 1.1-2.1 s,
Google TV 6.2-8.6 s). `/switch` stays the path without renditions (single audio, direct play, no `renditionId`) and
the fallback when an in-session switch fails. The picked language is remembered per account on the device and wins at
the next start (Chrome, iPhone, Apple TV, also over AVPlayer's German system-language autoselect). Android phone pass not
done (dev build ANR on the 2 GB AVD; Google TV covers ExoPlayer).

## Bugs fixed during the slice
1. A rendition without a matching engine track (tracks not listed yet / no match) would have been measured as a
   successful "server" wait without switching: now goes straight to `/switch` (`fallback: no_engine_track`), unit test
   "uses /switch when no engine track matches the rendition".
2. (slice 2 attempt 1, found by the attempt-1 agent, finished in attempt 2) ExoPlayer keeps an earlier audio override
   across a new source: after a forced `/switch` the server's default rendition played as the previous language.
   `applyServerTracks` now also selects the server's rendition on every new source (waits for
   `audioRenditions.length` engine tracks); expo-video engine labels tracks by `name` (HLS NAME) before `label`
   (ExoPlayer's label is only the localised language). Attempt 2 fixed a flaw in that fix: the mapping read the
   engine snapshot instead of the tracks of the event (unit test "selects the server rendition on a new source…" failed);
   `localTrackId` now takes the event's tracks. Live Google TV: 3/3 forced `/switch` runs play and tick the server's
   default rendition (table rows G5-G7).
3. Safari never applied the server's audio pick: Safari lists the forced subtitle with `kind: "forced"`, the web engine
   skips that kind, so the engine had 2 subtitles for 3 local ones and `applyServerTracks` waited (15 s) for the
   subtitle count before touching audio. With a German system language Safari autoselected Deutsch although the
   remembered preference made English the DEFAULT rendition (`def: en`, engine/native `de*`). Now audio and subtitles
   are applied independently, and the server's audio pick is re-applied (max 3) when the engine switches by itself
   afterwards, until the viewer picks a track. Tests: "applies the server rendition while the engine lists fewer
   subtitles (Safari forced kind)", "re-applies the server rendition when the engine picks by system language
   afterwards", "stops re-applying … once the viewer picks a track". Live Safari after the fix: `def: en`, native
   `en*`, chip/panel Englisch.
4. Web engine (native HLS path) did not listen to `video.audioTracks` `addtrack`/`change`, so a late track list or a
   native change left the snapshot stale; it now listens to them like it does for textTracks.
5. The 15 s `applyServerTracks` timer was never cleared on `stop()`, so jest needed ~16 s to exit (and the orchestrator
   saw `jest -w 2 src/player` not finish). The subscription is now kept in `serverTracksOff` and cleared on stop, on the
   next source and on a viewer audio pick; `jest -w 2 src/player` exits in 2.6 s, the full jest in 11.6 s, no
   `--forceExit`.
6. (slice 3) AVPlayer re-runs its automatic media selection when an audio option is selected: an in-session switch
   DE -> EN dropped the forced German subtitle (and EN -> DE turned it on) without the viewer asking, so the subtitle
   chip changed from "Deutsch" to "Aus" (iPad, before the fix). `switchAudio` now remembers the subtitle shown before an
   in-session switch and `holdSubtitle` puts it back when a tracks event shows another one (until the switch timeout;
   a viewer subtitle pick or a new source ends it). Tests "keeps the subtitle when the engine drops / adds one on an
   in-session audio switch (AVPlayer)" (fail without the fix). Live iPad + Apple TV: "Deutsch (forced)" stays on EN.
7. (slice 3) Same cause on a new source: `applyServerTracks` applied the server's subtitle only once, so after a
   `/switch` AVPlayer's own forced-subtitle pick won (Apple TV: `/switch` to DE turned "Deutsch (forced)" on although
   the request said `subtitleStreamIndex: -1`). Subtitles are now re-applied like audio (max 3 within 15 s) until the
   viewer picks; a viewer subtitle pick ends the re-apply. Test "re-applies the server subtitle when the engine picks a
   forced one by itself (AVPlayer)". Live Apple TV: 2 forced `/switch` runs keep the subtitle as it was.

## Decisions
- Decision per pick in `PlaybackController.selectAudio`: rendition (`inSessionAudioSwitch` + `renditionId` + an engine
  track that maps to it) -> `engine.setAudioTrack`, no `/switch`; direct play (`original`) keeps the engine switch;
  everything else `/switch`. An in-session switch that reports `audioError` (404/500 of the rendition), a fatal engine
  error, or no confirmation within `AUDIO_SWITCH_TIMEOUT_MS` (8 s) falls back to `/switch` (no stepDown, no notice
  unless `/switch` fails too).
- Mapping (`player/audio-renditions.ts`): engine track with the rendition NAME, else the only track in its primary
  language, else master order among same-language tracks, else master order only when the engine lists exactly the
  master's renditions and no language contradicts it.
- Switch done = engine confirms the track (hls.js: AUDIO_TRACK_SWITCHED, i.e. the first fragment is buffered) and the
  clock moves on while playing (paused: the confirmation). `/switch` done = new source past its start position.
  Samples land in `controller.audioSwitches` (`via`, `ms`, positions, `error`/`fallback`) for measurements.
- Remembered language: no client memory existed before (only the viewer's profile `audioLanguage`). Now the last
  picked language per account is stored on the device (`player/audio-preference.ts`, MMKV/localStorage, rendition
  BCP-47 code) and sent as `preferences.audioLanguage` on the next start; it overrides the profile language.
- One audio label: chip = language name + the layout the viewer hears; panel = language name (file title only when
  two tracks share a language) + codec/layout heard (`audioSpec`); Info = source -> delivered from the rendition.
  Language names everywhere via `languageName(code, locale, t)`.
- Error codes `unknown_audio_rendition`, `rendition_split_failed` in error-codes.ts with de/en texts; the web engine
  maps hls.js audio playlist/fragment errors with HTTP 404/500 to them (`engines/hls-audio-error.ts`).
- New source = the server's audio pick wins over the engine's own choice (ExoPlayer keeps old overrides, Safari/AVPlayer
  autoselect by system language): re-applied up to `MAX_SERVER_AUDIO_APPLIES` (3) within 15 s; a viewer pick ends it.
- `use-clock.ts` (attempt-1 change, kept): the clock re-renders only on a visible step (0.25 s), a seek, a new duration
  or 1 s more buffer instead of every 100 ms engine tick; state events always re-read. Reason: on the slow Google TV
  emulator every tick re-rendered the overlay. Covered by `use-clock.test.ts`; it does not change displayed values
  beyond 0.25 s.
- An audio switch never changes the subtitle selection (in-session and `/switch` alike), on every engine. AVPlayer's
  "forced subtitle follows the audio language" automatic selection is overridden on purpose: it would differ from
  hls.js, ExoPlayer and the `/switch` request. Whether forced subtitles should follow the audio language is a product
  question (BACKLOG Player).
- AVPlayer (iOS/tvOS) via expo-video exposes no track id: `label` = localised language ("Deutsch"/"Englisch"),
  `language` de/en, `name` = HLS NAME ("Deutsch · AAC 2.0"), `isDefault`, `autoSelect`; the engine's ids are `a0/a1` by
  list order and the mapping matches by `name` first (same as ExoPlayer). expo-video selects by displayName + locale.
- Native engines (ExoPlayer, AVPlayer) report no per-rendition HTTP error; their failure path is the fatal engine error
  or the 8 s timeout -> `/switch` (reasoned from code and unit-tested; not forced live on Android: the emulator was too
  slow to run a hook reliably, see Remaining).
