## Summary
Movies and Series in the TV/web rail (Home, Search, Movies, Series; Settings + profile at the bottom) and the Android
phone bar (5 entries; NativeTabs code from the same TABS list). One shared LibraryScreen: genre chips (All + server
genres), a segmented sort (Popular/Top rated/Newest), the shell's poster grid with captions and spec chips, paging on
hasMore with empty gated pages followed (<= 3 in a row) and dedupe, skeleton/empty/error+retry states, ambient following
the focused/hovered card. TV: rail -> chips -> sort -> grid, Back chain grid -> selected chip -> rail, focus memory,
title-safe row lift. Web: URL keeps genre/sort (push per filter, Back/Forward/reload restore), page titles. Deep links
streamarr://movies|series with the same params. Also fixed: episode-row whole-box ring (F1 leftover) and title-safe
scrolling of the focused episode box on the TV detail.

Intent: slice 1 = rail/tab entries, routes, deep links, i18n, Movies page on Google TV and web 1920x1080
(genre chips, sort, poster grid, paging, loading/empty/error states).

## Decisions
- Rail order follows C-detail.jpg: Home, Search, Movies (Film icon), Series (Tv icon); Settings + profile at the bottom.
  TABS in `navigation/tabs.ts` drives the rail, the web shell and NativeTabs, so the phone bar gets the 5 entries too.
- Routes: tab groups `(movies)/movies.tsx` and `(series)/series.tsx`; the shared detail group was renamed
  `(home,search)` -> `(home,search,movies,series)` so titles open inside the tab's own stack.
- One shared `LibraryScreen kind="movie|series"` (screens/library): reuses Search's grid layout, PosterCard (Home sizes,
  captions, spec chips), GlassChip (the one selected-chip style) and EmptyState/ErrorState/PosterCardSkeleton.
- Genre and sort live in the route params (`?genre=27&sort=top_rated`, `popular` omitted), so the URL and deep links
  (streamarr://movies?genre=..) carry them; unknown values fall back to All/Popular (`libraryParams`).
- Paging: `useLibrary` = useInfiniteQuery on `hasMore`; `fetchLibraryPage` follows empty (age-gated) pages up to 3 in a
  row; `libraryItems` dedupes by work id. Next page when the grid end is within 2 rows (onEndReached, TV focus on the
  last 2 rows) and while the grid is shorter than the viewport + 2 rows (a short grid never scrolls).

- Web filters push a route (`router.push`) so each genre/sort is a browser history entry; native uses `setParams`.
- Genre chips wrap (like Search's filter chips) instead of a horizontal ScrollView: the Android ScrollView swallowed
  D-pad Left at its start, so focus could not reach the rail.
- TV rail Right (pre-existing regression since F1's full-bleed content, also on Home/Search): the content's focus guide
  now starts under the rail, so Android's spatial search found nothing to the right. The rail traps Right and the
  shell's TV key handler calls `screens.focusActive()` (the screen's remembered element) on key-up.
- Pure helpers live in `browse/library.ts` (unit-tested); queries.ts keeps `useLibrary`/`useGenres`.
