# R0 — Redesign backend: per-title tint and spec summary

Status: done

## Intent
Server-side artwork palette (`tint`/`tint2`, cached, off the request path, contrast-adjusted) and a card spec summary
(resolution, HDR, codec, audio of the best version by qualityRank) on all viewer catalog payloads; OpenAPI + web/client types.
Test tree on Dev World 39310; do not touch 39300 (orchestrator override: no publish, no restart of 39300).

## Summary
- **Palette.** `Viewers/Artwork/PaletteExtractor` (SkiaSharp 4.153.1, MIT): decode, downscale to 64 px wide, deterministic
  k-means (8 clusters, luminance-quantile init, 12 iterations). `tint` = the hued cluster with the best score of chroma (30%),
  mid lightness (30%) and hue-family population (40%, clusters within ±25°), saturation clamped to 0.5–0.85, lightness 0.5–0.68
  and raised until the rounded hex has ≥ 3:1 against `#0A0C12`. `tint2` = the most populous cluster within ±35° of the tint hue,
  saturation 0.35–0.7 at lightness 0.20, darkened until white text has ≥ 4.5:1. Grey artwork gives low-saturation greys.
- **Cache, off the request path.** `ArtworkPaletteService` (singleton + BackgroundService): lookups are in-memory only; a miss
  is queued (bounded channel, deduplicated) and returns `null`. The worker fetches the TMDB `w300` rendition of the URL
  (only from the configured TMDB image host — no SSRF), max 8 MB, extracts, persists to the new `ArtworkPalettes` table
  (key = original image URL, `Version` = extractor version so algorithm changes recompute). 404/403/undecodable → stored as
  failed (retry after 7 days, then poster fallback applies); network/5xx → not stored, retried after 10 min. Title palette =
  backdrop, poster when the backdrop failed.
- **Spec summary.** `CatalogSpecDto { resolution, hdr, videoCodec, audio }` (`4K`/`1080p`…, `DV`/`HDR10+`/`HDR10`/`HLG`,
  `HEVC`/`AV1`/`H.264`…, `Atmos`/`7.1`/`5.1`/`2.0`/codec). `CatalogSpecStore` (in memory + `CatalogSpecSummaries` table)
  records the first non-dead release in quality order whenever a version list is looked up (movie versions, season
  availability, episode versions, playback "recommended"): per movie, per episode and per season; a series reads the best
  of its seasons (score: resolution, HDR, codec, audio). Lists never search indexers, so `spec` is `null` until someone looked.
- **Exposed on:** `CatalogItemDto` (search, discover rows: tint, tint2, spec), movie/series detail (tint, tint2), season
  response (series tint, tint2; each episode `spec`), `/viewer/watch/resume` items (`WatchStateResponse`: tint, tint2, spec —
  episodes use the series artwork via cached TMDB lookups), `/viewer/watch/next-up` items (series tint, tint2, episode spec).
- OpenAPI frozen, `web/src/api/schema.d.ts` regenerated, docs (`docs/api.md` §13, `docs/viewers.md`), NOTICE (SkiaSharp).

## Decisions
- DB tables (EF migration `AddCatalogArtworkAndSpecs`) instead of disk files: survives restarts, same backup as the rest.
- Palette computed lazily on first listing rather than on TMDB fetch: the server never fetched images before; the first list
  response of a new title has `null` tints, the next one has them (≈1–2 s for a full Dev World home).
- `WatchStateResponse` gained nullable `tint`/`tint2`/`spec` (filled on continue watching only) instead of a new DTO, so the
  client type for continue-watching items stays the same.
- Spec is device-independent (quality order, `qualityRank` 1) as specified; the version picker stays device-aware.
- Linux Docker: added `SkiaSharp.NativeAssets.Linux.NoDependencies` (runtime image is Ubuntu noble, glibc). Docker build not run.

Non-blocking findings:
- `ArtworkPaletteService`: bounded channel with `DropWrite` makes `TryWrite` return true while dropping, so with > 2048 pending
  images a URL stays in `_queued` forever (never computed until restart; `WhenIdleAsync` would never finish). Use `Wait` mode
  with a non-blocking check or `DropNewest`+count, or check `Reader.Count` first.
- Palette/spec failures log only at Debug, so a broken image host or missing SkiaSharp native lib would be silent in production.
- `CatalogSpecStore.Get` for a series scans all entries per list item (fine now, O(n·items) on large libraries).
- Continue watching resolves TMDB titles on the request path (cached client, so cheap) to find artwork.
- Known: BBB/Sprite Fright hues differ from the mockup; spec null until versions are looked up; amd64 Docker image not built.
