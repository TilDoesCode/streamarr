# I4 — Client: Apple TV native focus and Menu

Status: done (S1 code + build, S2 probe + live on the Apple TV 4K sim; worktree ../streamarr-i4, branch round-i/i4)

## Intent
Close the Apple TV gaps I3/F7/F8 left for native work: initial focus in the presented Versions/About sheets, Menu one
level at a time (sheet, library grid → chip, non-Start tab → Start, player overlay), focus after the player
("Zurück zu den Details"), the top tab bar hiding while Settings scrolls, plus the JS-only leftovers (last Versions card
glow, deep link over a detail) and the one-time VLCKit-on-tvOS check. Native code goes into one Expo module
(`client/modules/tv-native`), so it survives `expo prebuild`; nothing is hand-edited in `ios/`. The tvOS build runs in a
separate git worktree so the iOS dev build in the main tree stays untouched.

Research (root causes with file/line references, fix designs, tests, live proofs, build plan):
`docs/client/runs/driver/I4-research.md`.

## Plan summary

### S1 (2026-10-04 20:05-20:22, code only, no simulator; worktree ../streamarr-i4 at 604806f)
- Module `client/modules/tv-native` (Swift, `expo-module.config.json` platforms `["tvos"]`, podspec `:tvos` only):
  autolinking resolves with `--platform apple`, but `autolinking_manager.rb:76-78,163` skips a pod whose podspec does
  not support the target platform, so an iOS prebuild never links it (cached iPhone/iPad dev build stays valid); JS
  loads it with `requireOptionalNativeModule` only when `Platform.OS === 'ios' && Platform.isTV`.
  - A. Menu gate (`MenuGate`): one `UITapGestureRecognizer` (`allowedPressTypes = [.menu]`, `delaysTouchesBegan`)
    per scene window, delegate `shouldReceive press` = JS mode (`always`, `tabBar` = focused view inside the tab bar,
    `observe` = probe: records focus chain, controller tree and Menu recognisers before/after, never intercepts),
    `shouldBeRequiredToFailBy` = true while armed. On recognition it posts react-native-tvos'
    `RCTTVNavigationEventNotification` with `object: {eventType: "menu", eventKeyAction: 1}` (the emitter forwards
    `notif.object`, RCTTVNavigationEventEmitter.mm:49-52), so `BackHandler.ios.js` and every `useBackHandler` run.
  - B. `focus(tag)`: Fabric view by tag (`appContext.findView` → `RCTComponentViewRegistry`), waits for a running
    `transitionCoordinator` (owning VC chain / presenting / root), then `UIFocusSystem.requestFocusUpdate(to: target)`
    + `updateFocusIfNeeded`; if focus did not land and a `TVFocusHost` is an ancestor: the host's
    `preferredFocusEnvironments` returns the target once and the host (or a request to it) updates. Resolves whether
    focus is inside the target. `TVFocusHost` = `ExpoView` (`View(TVFocusHostView.self)`).
  - C. `attachTabBarScroll(tag)`/`detach`: first `UIScrollView` of the view → `setContentScrollView(_:for: .top)` on the
    ancestor VC whose parent is the `UITabBarController` (RNSTabsScreenViewController).
  - Probe: `debugFocus(tag?)` (focused responder chain, controller tree incl. presentations, Menu recognisers on the
    focused chain, observed Menu presses, `UIFocusDebugger.checkFocusability`/`simulateFocusUpdateRequest` for the
    target and the root view, `targetInRootView`); in dev builds exposed as `globalThis.__tvNative`
    (`debugFocus`, `setMenuMode`, `focusView`) for argent `debugger-evaluate`.
- JS (all Apple TV only; Android TV, phones, web unchanged):

    `native` = an RN `<Modal>` is open: its own Menu recogniser must keep working, so Sheet/Dialog claim it). Safety
    net registered at import (first `useBackHandler` import + root layout) = lowest-priority BackHandler listener: a
    claimed Menu that nobody handled disarms the gate until the claims change, so a stale claim never traps. Unhandled
    Menu with a back stack is already handled by expo-router's container listener (`fork/useBackButton.native.js`:
    `navigation.goBack()`), i.e. a TV sheet route closes one level.
  - `components/focus/tv-focus.ts`: `tvFocus(target)` (module on Apple TV, falls back to `requestTVFocus` if it

  - `use-tab-bar-scroll.ts`: `useTabBarScroll()` ref → attach on mount, detach on unmount.
