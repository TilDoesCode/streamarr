## Summary
Design system, i18n and TV focus primitives for the client, plus the `/dev/gallery` route.
- **Tokens** (`src/theme`): one source of truth — `colors.json` + `radius.json` feed both Tailwind
  (classes like `bg-surface-raised`, `text-foreground-muted`) and TypeScript (Reanimated needs static
  colours); `tokens.ts` holds spacing (4-pt), per-form-factor type ramps (display … label), layouts
  (gutter, card sizes, control heights, overscan-safe TV edges), focus tokens and motion. Cinematic
  dark palette (canvas #0A0B0F, raised surfaces), white primary actions (Apple TV/Netflix idiom),
  restrained violet accent only for watch state/selection, semantic success/warning/danger/info.
- **Form factor** `phone | tablet | tv | desktop-web` (`detectFormFactor`, shortest side / pointer
  type) and `useDesign()`; TV values are authored on Android TV's 960 dp canvas and scaled by
  width/960 (Android TV 1×, tvOS 2×). Replaced the M2.1 CSS-variable theme and `src/lib/theme.ts`.
- **Focus primitives** (`src/components/focus`): `Focusable` (Pressable; focus/press/hover as
  Reanimated shared values → no React render per D-pad move; web ring only on `:focus-visible`;
  `hasTVPreferredFocus` only on TV; disabled/preview not focusable), `FocusLift` (UI-thread scale
  1.08 cards / 1.06 buttons on TV, 3 dp white ring + glow, pressed 0.97, reduced motion → no scale),
  `useFocusState`, `FocusGuide` (TVFocusGuideView `autoFocus` memory, `END_OF_ROW` right trap),
  `useBackHandler`.
- **Components**: Text (type ramp + tones), Icon, Button (primary/secondary/ghost/destructive ×
  sm/md/lg, loading, disabled, focus turns white), IconButton, Badge, Tag, Skeleton (+ poster /
  landscape / text), ProgressBar, Spinner, Artwork (expo-image + designed fallback), Scrim, PosterCard,
  LandscapeCard, EpisodeRow (row highlight + ring, played/progress/unavailable), Shelf (FlatList row:
  TV focus memory incl. remount restore via `memoryKey`, snap-to-gutter, end-of-row stop, desktop
  pager arrows, phone snap), Hero, EmptyState, ErrorState (code → localized title/message, generic
  fallback keeps the code, suggested actions), Dialog (centered, preferred focus, trapped), Sheet
  (phone bottom sheet with drag-to-dismiss; side panel on tablet/desktop/TV), SheetItem, Toast
  (non-focusable, live region).
- **i18n**: ICU MessageFormat via `i18next-icu` (real ICU plurals/select/number), de + en, formatjs
  `Intl.Locale` + `Intl.PluralRules` polyfills (Hermes lacks both; verified on device), device

  localStorage) with `useLanguagePreference` / `setLanguagePreference` / `useDeviceLanguageSync`,

## Decisions
- Kept NativeWind as the styling system (adopt, don't add a second one), but moved the colour source
  from CSS variables to JSON so Tailwind and TS (Reanimated) share it; alpha modifiers now work.
- Sizes that must scale on TV come from `useDesign()` (style props), colours via tokens/classes.
- Focus state lives in shared values (not React state): cheapest on the JS thread for rows of cards.
- Row memory is native (`TVFocusGuideView autoFocus`); JS memory (`memoryKey`) only for remounts.
- Horizontal groups trap focus only at the right end; the left edge stays open for the M2.4 rail.
- Shelves use FlatList, not FlashList: FlashList recycles views, which breaks native focus memory;
  react-native-tvos also augments VirtualizedList for TV focus. FlashList stays for long grids.
- TV scroll positioning via react-native-tvos `snapToAlignment="item"` + `scrollSnapAlign="start"`
  (rows land under the 27 dp overscan margin, focused card at the gutter).
- ICU instead of i18next's `_one/_other` suffixes (spec says ICU; translators know it); strings use
  `{name}`. `returnObjects` is not usable with ICU → leaf keys only.
- MMKV added now (PLAN §2 stack) for the device-level language override; M2.3 reuses it.
- Technical format labels (4K, HDR10, Dolby Vision, Atmos) are constants (`src/lib/media-labels.ts`),
  not translations.
- Gallery route exists in all builds (deep link `streamarr://dev/gallery`); only the link is dev-only.
- M2.1 review follow-ups done: `android`/`tv:android` scripts use `--no-clean`; focus ring no longer
  a border class; multi-line comments collapsed; `expo-linear-gradient` now used (Scrim); unused
  theme exports gone; colour lint extended (Tailwind `[#hex]`, template literals, `rgb()/hsl()`);
  i18n test rewritten as a leaf walk; phone no longer receives `hasTVPreferredFocus`.

### Blocking
1. **Google TV: focus goes off-screen in the Colors section of `/dev/gallery`.** `GalleryColors`
   uses `GallerySection` with the default `snap` (true). The section has 40 swatches in 7 rows, which is
   taller than the 540 dp screen. The page snaps the section top under the overscan margin and does
   not scroll further. Walking down from `background`: `foreground-subtle` → `accent` →
   `warning-muted` → `destructive-foreground` are fine. The next down lands on `popover-foreground`,
   which is clipped at the bottom edge (uiautomator bounds `[96,1006][344,1080]` on 1920×1080, and
   `describe` reports `Focused: (no label)`). The next down lands on the scrim/shadow row, which is
   completely off-screen (`describe`: `Focused: (none)`, no focused node in the dump, no ring
   visible). Reproduced twice, before and after a relaunch. Screenshots:
   `googletv-verify-colors-focus-clipped.png` and `googletv-verify-colors-focus-offscreen.png`. This
   breaks "visible focus on every element". The builder's D-pad transcript stops at the states
   section and never reached this part. `GallerySection` documents the rule ("Disable for sections
   taller than a TV screen; mark their children instead"), but Colors does not follow it. The
   pattern recommended to later tasks (snap sections + `snapToAlignment="item"`) has this trap for
   any tall section, such as grids.

### Non-blocking
1. The no-literal-text test misses ternaries and fragments. These probe lines passed:
   `<Text>{flag ? 'Yes please' : 'No thanks'}</Text>`, `label={flag ? 'Resume now' : 'Start over'}`
   and `<>{'Fragment literal'}</>`. It also scans only `.tsx` files.
2. The colour lint misses named colours and Tailwind palette classes: `backgroundColor: 'white'`,
   `'black'`, `className="bg-white text-red-500"` give 0 ESLint errors. The spec only names raw hex,
   so this is not a spec violation.
3. Web Dialog/Sheet: the first keyboard focus lands on the full-screen dismiss scrim (`Ausblenden`,
   `outline: auto`). The browser outline then frames the whole viewport
   (`web-verify-dialog-scrim-focus.png`), and the scrim is part of the Tab cycle
   (Cancel → Remove → scrim). `preferred` initial focus only works on TV. Space does not activate a
   `SheetItem` (`role="radio"`) on web; Enter does.
4. Focus and hover make some controls darker. An unselected `Tag` uses `colors.input` (10% white)
   when focused or hovered, which is darker than its resting `secondary` (14%). On TV a focused
   unselected tag turns near-black with a ring, while buttons turn white. The secondary Button hover
   on web also darkens.
5. When a Dialog or Sheet opens on TV, the trigger button keeps its lifted, ringed look under the
   scrim, so two focus rings are visible.
6. The TV Sheet side panel has 24 dp horizontal padding. The focused option's ring reaches about
   940 of 960 dp, outside the 48 dp overscan-safe gutter.
7. On TV the Progress section (spinners) is never fully on screen. It has no focus stop, and the
   snap jumps from the last error state to Loading, so the TV gallery cannot show spinners for
   screenshots.
8. Dead code and speculative API:
   - Unused components and context: `src/components/ui/icon.tsx` (`Icon` is never imported) and

   - Unused tokens and props: `FocusTokens.enabled` (never read), `aspect.backdrop`, `easing.inOut`,
     Scrim `direction: 'down'`, ProgressBar `tone: 'light'`, PosterCard `showCaption` (never false).
   - Test-only API: Focusable `lift`/`ring`/`radius`/`contentStyle`/`onFocusChange` are used only in

   - Unused dependencies: `@rn-primitives/portal` (a `PortalHost` with no `Portal` users) and

9. `Shelf.getItemLayout` reports offsets without the leading gutter on purpose, so that
   `initialScrollIndex` lands at the gutter. As a side effect, FlatList's window math is off by the
   gutter. Setting a `contentOffset` for the restore would be the honest option.
10. There is no unit test of the TV path (for example with `Platform.isTV` mocked): the
    FocusGuide trap/autoFocus mapping and `hasTVPreferredFocus` on TV are only verified manually.
11. On web, every shelf is a long Tab sequence (12–14 stops) with no arrow-key roving (M5 web
    keyboard work).
12. German copy: "Deine Bibliothek, bereit wenn du es bist." needs a comma ("bereit, wenn du es bist").

### Design critique
On TV and desktop web it mostly reads as premium:
- The dark palette is cinematic, with the Apple TV / Google TV idiom where focus turns a control
  white, plus lift and glow.
- The hero has layered scrims and a clear type hierarchy.
- Violet is kept for progress and selection only.
- Episode rows, the error states and the side-panel sheet feel native.

Weak spots:
- The hero backdrop starts with a hard edge under the gallery header.
- A focused unselected tag goes darker (item 4).
- The static "pressed" preview looks the same as the rest state.
- System fonts only.
- Two-line captions under every poster make TV rows busy; Google TV shows titles on focus.
- The icon-button size labels are misaligned.
- The 8 dp gap between dialog actions lets the focused Cancel ring almost touch Remove.

## Fix round 1

### Blocking: focus off-screen in tall sections (Colors) — fixed at the root
- Root cause: react-native-tvos `ReactScrollViewHelper.findScrollSnap` walks up from the focused view to
  the ScrollView and the **outermost** `scrollSnapAlign` wins. `GallerySection` put `start` on every
  section, so in a section taller than the 540 dp screen every focused swatch snapped the *section* top
  and the page never scrolled further (rows 6/7 clipped / off-screen). Marking children could not help
  while the section itself had a snap target, and remembering to pass `snap={false}` was the trap.
- Fix: new `FocusSection` (`src/components/focus/focus-section.tsx`). On TV it measures itself
  (`onLayout`) and snaps its top only while it fits (window height - 2 x overscan - ring room); a taller
  section sets no snap on itself and provides `ItemSnapContext = 'center'`, and every `Focusable` inside
  sets `scrollSnapAlign="center"` on itself, so the focused item is always centred (clamped at the page
  ends). `GallerySection` is a `FocusSection` now; its `snap` prop and the manual per-episode `center`
  wrappers are gone. Explicit inner targets still work where they are outermost (Hero, Shelf, the state
  frames).
- Pattern for later tasks (README + notes below): page blocks are `FocusSection`s; never put
  `scrollSnapAlign` on containers that can be taller than the screen.

### Root cause of the invisible Sheet (Blocking 1) and the stale focus visuals (Non-blocking 1)
- Reanimated 4.5.1 enables the static flag `FORCE_REACT_RENDER_FOR_SETTLED_ANIMATIONS` by default. An
  animated style that has settled stays in the native props registry for only 2 s
  (`ReanimatedModuleProxy::getSettledUpdates` → `getUpdatesOlderThanTimestamp(now - 1000, now - 2000)`). A
  500 ms JS interval (`PropsRegistryGarbageCollector`) has to pick it up between 1 and 2 s after it settles
  and `setState` it into the component's React props. If that timer is late, the entry is deleted unseen.
  The next React commit is based on React's own tree, so it restores the stale React props on every node
  whose entry was dropped.
- On Google TV that meant three things: the Sheet panel went back to its initial `translateX = width`
  (the `useAnimatedStyle` initial value from before the JS-started `withTiming`), the backdrop went back to
  opacity 0, and the trigger's ring came back. That is exactly the verifier's state: Modal window open,
  `sheet` at x=1920, no focus, scrim transparent, ring on "Open sheet". The same mechanism explains the
  half-focused previews: some views were synced and others were dropped. The Dialog animates with a
  mount `entering` Keyframe, so its resting state is its React style, and it never failed.
- **Deterministic repro.** A scratch probe (removed) blocked the JS thread for 3 s, 0.5 s after the Sheet
  opened. Then one `down`. Result: `FOCUSED: (none)`, no `sheet` node, 2 app windows, and the trigger
  ringed under a transparent scrim (`googletv-fix2-repro-stall-sheet-invisible-before-fix.png`).
- **Timer measurements** (Argent `debugger-evaluate`, 100 ms interval gap detector):
  - After each D-pad press on the emulator, JS timers fire about 1.0–1.1 s late. A Hermes CPU profile over
    two presses shows the JS thread idle (774/774 samples in `[root]`), so this is timer scheduling, not
    JS work.
  - On the first Sheet open, a 500 ms timer fired after 1125 ms.
  - Late timers are enough to miss the 1–2 s window. I could not isolate why UI automation made it more
    likely in the verifier's sessions.

    in fix round 3).
