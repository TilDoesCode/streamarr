Status: done

## Summary
The viewer search now finds a title while it is being typed: a query matches when every query word is the start of a
word of the title (localized or original), case-, accent- and umlaut-insensitive (ä = a = ae, ß = ss), with hyphens and
apostrophes splitting words. Results are ordered exact title > title starting with the query > word-start matches >
the rest of TMDB's results in TMDB's order; the age policy runs after the ranking, unchanged. The same matcher drives
Dev World's canned TMDB, which is where Q2-03 came from (it only accepted whole words).

## Decisions
- One matcher in Core (`TitleMatcher`), used by the product ranking and the Dev World fixture, so the fixture behaves
  like the rule the product documents.
- The product cannot add titles TMDB does not return; it reranks TMDB's candidates. The real TMDB search already
  matches word starts as you type (assumption, not verifiable here without a TMDB key); the ranking makes sure an exact
  or prefix hit is first even when TMDB orders by popularity.
- "Alternative titles the endpoint already uses": the endpoint only has TMDB's `title` and `originalTitle` (TMDB search
  results carry no alternative titles); the canned TMDB also matches `titleDe`, as TMDB matches every translation.
- Two spellings per word (folded ä -> a, transliterated ä -> ae): a typed "Waech" and "Wach" both find "Wächter";
  whole-string exact/prefix compares one spelling at a time.
- No contract change (ordering only); OpenAPI unchanged, contract `--frozen` green.
