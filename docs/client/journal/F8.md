- Sign-out cause (18:10-18:15): server `ViewerSessionService.RefreshAsync` rotates on receipt and replays the last
  rotation for the previous refresh token only for 30 s (`RotationGrace`), after that the previous token = reuse ->
  session revoked -> `refresh_token_reused` ("Signed out for your security"); an unknown/revoked/evicted token -> 401
  unauthorized -> `refresh_session_expired` ("Your session has ended"). Dev World 39300 DB (read-only sqlite3): anna has
  17 active sessions + 6 revoked `session_limit` (MaxSessionsPerViewer 20; every run's fresh sign-in evicts the least
  recently seen session) — 3 of them Google TV sessions (created 10-01 23:54, 10-02 10:51, 10-02 11:11; revoked 10-04
  15:37/16:07 UTC). Reuse-revoked rows older than 1 day are deleted on each sign-in, so older reuse events are gone.
  Emulator-side: a snapshot boot restores the vault from snapshot time; any rotation after the snapshot makes the
  restored refresh token "previous" (reuse) or unknown (expired) — emulator-only. Real users: refresh request reaches
  the server, the answer is lost (Wi-Fi drop) or the app is killed before the vault write -> next refresh > 30 s later
  with the old token -> reuse -> sign-out. Client fixes: re-send the same refresh token after a lost answer (1 s, 3 s,
  inside the grace the server replays the pair), treat an ok response without a readable body as lost, persist the
  rotated pair to the vault before the in-memory cache can hand it out. Kill-during-refresh needs the server (below).

## Server request (for the orchestrator / backend track)
`ViewerSessionService.RefreshAsync`: when the presented token is `PreviousRefreshTokenHash` and the rotated pair was
never used (no request authenticated with the new access token, new refresh token not presented — e.g. a
`RotationConfirmedAt` set in `ValidateAsync`/`RefreshAsync`), replay the last rotation (`ReplayRotation`) instead of
revoking, for up to the refresh lifetime (or at least 24 h). Reuse after the new pair was used still revokes (theft
detection unchanged). This closes "app killed after the server rotated" on real TVs. The client already re-sends
within 30 s; jest models both rules (refresh-rotation.test.ts). Optional: Dev World runs could revoke their own
sessions (sign out) so anna stays below the 20-session cap.
