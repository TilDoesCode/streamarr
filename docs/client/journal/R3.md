## Decisions
- Follow-ups:
  - R2 verifier #1: `FeaturedStore` keeps the latest (undebounced) focus as `pending`; `playTarget()` returns it and
    `flush()` applies it. Home Play/Pause plays `playTarget()`; when it differs from the hero, the store is flushed and
    the title plays once its detail query has the work id (`playWhenReady`). Unit test in featured.test.ts.
  - R2 verifier #2 (focus return to the opener): cause was Home's `hasTVPreferredFocus` on the first card of row 0.
    When Continue watching reorders after the player (the played title moves to the front) a new first card mounts
    with hasTVPreferredFocus and steals focus from the restored opener. Home now sets it only until a row has taken
    focus (`focusTaken` state set in the row wrapper's onFocus); cold start still focuses the first card. P1's
    ScreenFocusScope contract unchanged. Verified on the device (no unit test: RNTL cannot observe native TV focus).
  - Search grid caption (#5): on the large shell the type word is dropped when spec chips share the line ("2010" +
    chips); phones keep "Movie · 2010".
  - Sign-in split (#6 + orchestrator): web centres heading and form on one vertical axis (flexGrow + justifyContent),
    the root clips (`overflow: hidden`) so no page scrollbar; edges `s(96)` on TV and web (TV value unchanged: 48 dp).
    TV keeps the form high (IME).
  - Web keyboard lift dim: already worked (hero art container opacity 0.45 measured while a lower row is lifted); the R2
    open-issue line was stale. Nothing changed.
  - Tab order (#7): on web the rail renders first in the DOM (zIndex 2 keeps it painted above the content), so the first
    Tab lands on the rail's first item; row pager arrows are `focusable={false}` (tabIndex -1, mouse only).
  - Tablet readability (#9): `useShell().font(value, min)` / `shellFont()` floors scaled text on web/tablet (TV scales
    exactly): spec chips ≥ 11 px, card titles ≥ 15 px, sublines ≥ 13 px, panel text ≥ 13 px, mono release ≥ 11 px.
  - Avatar colour (#12): `profileColor(viewerId, accounts)` hashes the viewer id (FNV-1a) into the 8 Aurora avatar
    slots and probes to the next free slot on collision, so colours stay distinct per device and equal across devices.
    Viewer id only (not the server URL): the same server has different URLs per device (10.0.2.2 vs localhost).
    Stored colours are recomputed on load (one-time change of existing tiles).
- Detail on the large shell (`screens/detail/large-detail.tsx`, `browse/version-panel.tsx`):
