## Decisions
- One rail implementation for Android TV only; tvOS keeps the native top tab bar (NativeTabs) and Android phones the native
  Material bottom bar — both through the same `NativeTabsShell`.
- Exit confirmation dialog instead of double-press (explicit, localized, focus-safe on Google TV).
- Tab Back: TV `firstRoute` (Back from Search/Settings returns Home, then exit), phones `initialRoute`, web `fullHistory`
  (fix round 1; browser Back/Forward follow every visited tab, `history` replaced entries of revisited tabs).
- TV and web draw their own page headings; phones/tablets use native stack headers (large titles on iOS, transparent on
  detail screens); web detail screens show the JS stack header with a back link.
- Player route lives outside the tabs (full screen, no rail/tab bar), so M4.2 gets the whole screen.
- Focus restoration: native `TVFocusGuideView autoFocus` forgets across the tab screen detach/re-attach, so each screen also
  keeps a JS reference to the last focused `Focusable` (`FocusMemoryContext`) and asks it for focus; the native memory is the
  fallback. `requestTVFocus` on a detached view focuses on attach (react-native-tvos `focusOnAttach`), so no timing hacks.
- Web nav items are anchors (`href`) so Enter, middle click and "open in new tab" behave like links.
- Search asks for the server maximum of 20 results (M4.1 adds paging/filters).
- Onboarding keeps the M2.3 exit (`dismissAll()` + `replace('/')`): on the web the sign-in entries are left behind the
  current entry, so browser Back from Home after signing in does not return to onboarding (verified: `history.back()` stays
  on `/`).

## Notes for next tasks
- New screens inside a tab stack get TV focus restore for free (`TabStack` wraps them in `ScreenFocusScope`); use `Focusable`
  (directly or via Button/cards) so the JS focus memory sees them. Screens outside the tabs (player) are not wrapped. The TV
  shell hands focus over through `ScreenFocusProvider`/`useScreenFocusHost` (fix round 1), not module state.
- Android TV: never make a view focusable by accident. `Text selectable` is dropped on TV by `Text` (a selectable TextView
  steals focus on attach and then drops it); if you render RN `Text` directly on TV, do not pass `selectable`.
- Links to titles/player: `titleHref(item)` / `playHref(playbackId, work)` in `src/navigation/routes.ts`. The play route is a
  placeholder (`screens/player/play-screen.tsx`) for M4.2; the movie Play button passes `playbackId: 'preview'`.
- Detail screens are placeholders with live headers (`detail-parts.tsx` hooks `useMovieDetail/useSeriesDetail/useSeasonDetail`);
  M4.1 fills versions, "more like this" and continue watching.
- Catalog search `limit` must stay ≤ 20.
- TV Back: `TvRailShell`'s handler returns false for `navigate`, so expo-router's own Back handling pops the stack / tab history.
- Device testing: `/tmp`-style helpers used here — uiautomator dump for the focused node on Google TV, CDP `Input.dispatchKeyEvent`
  for trusted Enter/Shift+Tab in Chromium (Argent's Enter lacks the key code), CDP `Emulation.setDeviceMetricsOverride`

- Root cause (jdb trace `docs/client/runs/m24-raw/m24f-jdb-trace.txt`, breakpoints on `View.handleFocusGainInternal`/`unFocus`/
  `ReactViewGroup.requestFocus`): the rail's tab switch asks the new screen's guide for focus while its fragment is not
  attached (`focusOnAttach`). On attach the FlatList content is still clipped (`removeClippedSubviews`), so the first focusable
  is the ReactScrollView itself. When the clipped rows are attached, the EmptyState's `selectable` message
  (`ReactTextView.onAttachedToWindow` → `setTextIsSelectable(true)`) becomes focusable-in-touch-mode, `ViewRootImpl.
  focusableViewAvailable` hands it focus (the focused ScrollView is FOCUS_AFTER_DESCENDANTS), then react-native-tvos forces
  TextViews non-focusable on TV → `clearFocus` → `rootViewRequestFocus` → the screen guide (autoFocus) tries its
  lastFocusedElement (that text, attached but unfocusable) and returns true without focusing anything. Same path on every
  D-pad press → D-pad dead. Race: it depends on whether the rows are attached before or after the guide's attach.
- Fixes: (1) `Text` never passes `selectable` on TV (meaningless there; removes the focus thief everywhere: EmptyState/ErrorState
  messages, form messages, settings about values); (2) `ScreenFocusScope.restore` retries (10 × 120 ms) until one of the screen's

  and the focused search field; (4) the shell ↔ screen hand-over is a context (`ScreenFocusProvider`/`useScreenFocusHost`)

  restores Home's focus instead of leaving it on the rail. Debug code removed. Web nav anchor typed without `as object`.
