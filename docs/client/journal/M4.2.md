## Decisions
- Production controller `src/player/controller.ts` instead of extending the lab `PlayerSession` (lab stays as is).
- Player strings in their own i18n namespace `player` (`usePlayerT`, typed keys via a local Leaves type): adding them
  to the typed default namespace broke TypeScript (TS2589) in unrelated screens.
- Resume choice: the play route asks only when it has no `start` param and the server's saved position is ≥ 30 s and
  not in the last 30 s; browse screens already pass explicit Resume/Start over (`start=0` is now kept in the URL).
- TV key map: overlay hidden → player-keys capture D-pad + media; OK/playPause toggle; ◀/▶ and rewind/fastForward
  scrub (−10/+30, key-repeat accelerates 10→30→60→120 s, commit 700 ms after the last key); ▲ opens the overlay on
  the button row; ▼ opens it on the seek bar (D-pad stays captured there); on the button row native focus moves;
  Back: panel → overlay → exit. Overlay stays mounted (opacity) so TV focus never lands on nothing.
- Up-next: 15 s before the end (or on ended) for episodes with an aired next episode (season detail, else first of the
  next season); 10 s countdown; Play now has preferred focus; Cancel/Back dismiss for this episode.
- Step-down: first engine error per playback revision → `switch {stepDown:true}` at the current position + notice.
- Progress: every report goes through `ProgressQueue` (MMKV `streamarr.progress-queue`, per account; transient
  failures retried 2/5/15/30/60 s, flushed on foreground); AppState background → report + pause.
- Dev-only `globalThis.__streamarrPlayer` (only `__DEV__`) to force engine errors in verification.
- VLC start position via the module's `time` prop, not `:start-time` (which makes libVLC's clock relative).
- Switches that keep the release carry the current audio/subtitle (client-side subtitle picks are unknown to the server).
- ▲ releases the D-pad capture synchronously; the overlay never pulls focus back when native focus is already on the row.
