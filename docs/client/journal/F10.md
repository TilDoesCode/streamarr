# F10 — The player catches and explains every state

Status: planned

## Intent
Implement the user requirement of 2026-10-05 00:50 (PLAN § 5 "I"): the viewer never sees a generic error, a black
screen or a frozen picture. Every player state is either compensated automatically (wait, reload, new start at the
position, lower quality, step-down, other version) or explained with one specific de/en hint and an action. One
health watchdog per engine (frames, clock, audio), one error taxonomy with a compensation ladder and budgets, jest
tests per matrix row with fake engines, then live runs with Dev World fault injection (B12) on every engine.

F10a (research + design, no devices) is done; F10 S1–S9 are the build slices.

## Server follow-ups found (not part of F10/B12)
- Seek back > 15 min inside one long transcode run waits on a run that never rewrites the retained-away segment →
  90 s hang → `504` (inferred from `TranscodeSessionManager.cs:358-366`, `:614-633`; not reproduced).
- Audio fallback flag for `/switch` (convert the selected track to AAC) for the ladder step **A**.
- Optional `playbackAlive` in the progress answer (a dead `playbackId` answers 200 today).
- `Retry-After` on `503 segment_evicted`; a per-wait cap (~25 s) so client and server timeouts agree.
