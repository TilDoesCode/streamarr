## Locking, migration, accounting and load evidence

**Locking/CAS.** Reviewed lock ordering: download lock precedes the lifecycle write transaction; session revocation commits and disposes its transaction before acquiring download locks. No reversed acquisition was found in the reviewed paths. Forced `IOException` inside a lifecycle transaction releases it and the keyed lock; next renewal is **200**. While a first renewal is gated, **30 cancelled waiters** all cancel, then **30/30** new renewals return 200, final GET is 200, and **ActiveKeyCount=0**. Writer-contention renewals, mixed lifecycle tests and the full suite produced no busy-timeout/retry storm or deadlock. These finite checks do not establish every multiprocess schedule. Immediate SQLite transactions serialize the tested writes; the revision predicate remains an additional safeguard.

**Response-time session checks.** A second component probe pauses the list's SQL reader, commits sign-out, then resumes: `{revoke:204,status:401,dtoReturned:false}`. The pending-poll check also returns 401 without a file URL. Original cross-viewer/error/admin-list/log checks pass; admin DTOs carry no capability. The new major issue concerns an already-known capability whose rotation is cancelled, not a URL in the 401 body.

**Migration.** `seed-legacy` runs the **archived assembly's original hardening migration** and seeds its actual old schema. `migration-probe` then runs the new assembly against that already-applied history, proving that success does not depend on rerunning the edited migration. A separate DB starts at the pre-DL schema, retains an existing viewer, advances to the original Downloads table, receives duplicates/colliders, then runs both new migrations. Both preserve **9/9 records**: distinct pipe tuples, three true case variants (oldest gets `d:phone`, others null), separate `Ä`/`ä` devices, session-keyed and no-reference rows. Existing viewer remains `allowDownloads:true`, no override limit; new row revision/security generation start at zero.

**Background accounting.** Two overlapping Range requests plus an initial range yield **327,680** bytes. A concurrent complete waits for a held writer; after release the persisted count is **exactly 327,680**, including after graceful restart. No duplicated increment or overwrite was observed. A controlled **SIGKILL of the owned Dev World PID 75921**, with a writer holding back the next accounting increment, loses the known **65,536 unflushed bytes**: baseline 65,536; sent total 131,072; persisted after restart 65,536. The same capability/ETag resumes the identical range (SHA-256 `8934c11782513efb68f2385fc6beb4f1080f3fb7cf39339591249e8c1fbeca99`). This confirms in-memory telemetry is best effort on abrupt death; it does not affect downloaded media. V3-02 is the avoidable loss on an orderly stop.

**Versions latency.** Same unmodified `ViewerVersionsLatencyTests` on **d9f040a2** and archived **a48a0755**, interleaved three times per mode/tree after the full suites finished. Each case measures ten warm cached requests for 150 versions; all **12/12 test executions passed**:

The threshold is 250 ms. The versions test and catalog implementation have **no diff** between these commits; ordinary versions requests do not acquire the new download lifecycle locks. No other lane's processes were changed. Moderate added load still shows similar timings on both trees.
