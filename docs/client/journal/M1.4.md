# M1.4 — Server remux (direct stream)

Status: done (pending-ios: Apple mediastreamvalidator / AVPlayer checks need Xcode)

## Intent
Add a stream-copy ("remux") tier to `server/src/Streamarr.Server/Transcoding/`: planner decides
direct → remux → transcode with reasons; keyframe index from Matroska Cues / MP4 stss+stts
(ffprobe fallback); keyframe-accurate VOD playlist; video copied into fMP4 HLS (hvc1, HDR
signalling, exact CODECS), audio copied or converted, text subtitles as WebVTT renditions;
capacity accounting with lower weight; admin UI shows the mode. Validate with ffprobe + hlssim
(including a far seek) on Dev World media; publish Dev World when green.

### Design (decisions)
- **Modes.** `TranscodePlanner.Decide` returns `mode` direct | remux | transcode plus structured
  `reasons[] {code, message, params}`. Direct = existing blockers empty. Remux = video decodable by
  the client (codec h264/hevc/av1 in client list; 8-bit 4:2:0 H.264 / HEVC Main|Main10 / AV1 Main;
  bit depth vs `supports10Bit`; HDR format vs `hdrFormats`/`supportsHdr`; DV profile 8.x/7 → base
  layer (HDR10 or HLG), profile 5 → transcode; not interlaced; within the *request's* maxHeight /
  maxBitrate — server transcode caps do not apply to copies) but container/audio/subtitle is not.
  Else transcode. Sessions: `mode` request field auto|remux|transcode, **default transcode** so every
  existing caller (web UI, hlssim, tests) keeps the unchanged transcode path; `mode=remux` that is
  impossible → 422 `remux_not_possible` with reasons. `/transcoding/plan` defaults to auto.
  Direct-play checks now also use only the request limits (server output caps only bound transcodes).
- **Keyframe index** (`KeyframeIndexService`, cached 10 min per source): range reads over the loopback
  `/api/v1/stream/{token}` (HTTP Range) or the sample file. Matroska: EBML header → SeekHead (one
  nested SeekHead level) → Info (TimecodeScale), Tracks (first video TrackEntry: number, CodecID,
  CodecPrivate) → Cues (CueTime for that track, CueClusterPosition → byte sizes). MP4: walk top-level
  box headers to `moov` (≤ 64 MiB), first `vide` trak: stts/ctts/stss/elst (+mvhd for empty edits),
  keyframe PTS = dts + cto − elst media_time (+ empty edit), stsz for byte sizes, stsd config box.
  Fallback: ffprobe packet scan (`-select_streams v:0 -show_entries packet=pts_time,flags,pos`,
  streamed line by line, time budget 20 s), else transcode with reason `keyframe_index_unavailable`.
  Codec config from the container (avcC/hvcC/av1C) or `ffprobe -show_data` extradata (Annex B ok).
- **Segment planning.** Output timeline = source PTS − format start_time (what `-copyts
  -start_at_zero` produces). Target boundaries n×6 s; each maps to the first keyframe ≥ it; several
  targets on one keyframe merge (no short segments after long GOPs); a tail < 1 s merges into the last
  segment; first segment starts at 0; EXTINF = real durations; TARGETDURATION = ceil(max). Index is
  rejected if a segment would exceed 30 s.
- **ffmpeg for copy runs.** One process per run: video `-c:v copy` (+`-tag:v hvc1` for HEVC), audio
  copy or converted, fMP4 to **stdout**; a C# `RemuxSegmenter` reads the box stream, writes
  `init-{run}.mp4` (ftyp+moov) and assigns each moof+mdat pair by its video presentation time to the
  planned segment, writing `{n}.m4s` atomically (tmp+rename) as soon as a fragment reaches the next
  boundary (no extra GOP latency); the final segment is written only on a clean ffmpeg exit, never
  after a kill. The rest of the session machinery (file-exists serving, Front(), throttle, retention,
  idle stop) is reused unchanged.
- **Seeks.** Restart at the segment's keyframe k with `-ss k + 3/23 + min(0.02, gap/2)` (gap = next
  keyframe), so both the Matroska dts heuristic and SEEK_TO_PTS demuxers land exactly on k; with
  `-copyts -start_at_zero` the timestamps are the same as in a run from 0; fragments before the target
  segment (early landing) are discarded by the segmenter.
- **Audio.** One muxed audio rendition; switching audio = re-plan (new session with
  `audioStreamIndex`, M1.3 `/switch`) — simpler and robust with one ffmpeg per session. Copy when
  the codec is fMP4-deliverable (aac, ac3, eac3, flac, opus), in the client's list, and channels ≤
  `maxAudioChannels`; otherwise ladder: E-AC-3 5.1 (640k) → AC-3 5.1 (640k) → AAC stereo (settings
  bitrate) by client support and `maxAudioChannels`.
- **Subtitles.** Every text stream (subrip, ass/ssa, webvtt, mov_text, text) becomes an
  `EXT-X-MEDIA TYPE=SUBTITLES` WebVTT rendition (`subtitles/{index}/main.m3u8`, segments aligned with
  video). Each run adds `-map 0:{i} -c:s webvtt -f webvtt -flush_packets 1 sub-{i}-{run}.vtt`; the
  server parses complete cues, dedups across runs, and serves segment n with
  `X-TIMESTAMP-MAP=MPEGTS:0,LOCAL:00:00:00.000` and every cue overlapping the segment. A segment is
  complete once the A/V run passed segment n+2 (or ended cleanly). Image subtitles (PGS, VobSub, DVB)
  → `deliveredAs: none` + reason `subtitle_not_deliverable` so the client can offer VLC/burn-in.
- **CODECS.** Video from the decoder configuration record (avcC → `avc1.PPCCLL`; hvcC →
  `hvc1.[space]profile.compat(reversed hex).(L|H)level.constraint bytes`; av1C → `av01.P.LLT.DD`),
  fallback from ffprobe profile/level. Audio: aac LC/HE/HEv2 → mp4a.40.2/5/29, ac-3, ec-3, fLaC,
  opus. `VIDEO-RANGE` PQ (HDR10, DV 8.1/7), HLG (HLG, DV 8.4), else SDR. BANDWIDTH = 1.1 × peak segment
  bitrate from index byte offsets (MKV cluster positions / MP4 stsz), AVERAGE-BANDWIDTH = mean;
  fallback source bitrate × 2.
- **Capacity.** Remux runs are counted separately: new setting `maxConcurrentRemuxes` (default 8,
  1–64) with its own `503 remux_capacity`; transcode slots unchanged.
- **Contract.** Plan: `mode`, `reasons[]`, `remuxPossible`, `subtitles[]` (index, codec, language,
  title, forced, default, textBased, deliveredAs), `keyframeIndex` {source, keyframes, buildMs},
  target `videoRange`, `audioCodec`, `videoCopy`. Session/created: `mode`. Request: `mode`,
  `subtitleStreamIndex`; client: `hdrFormats`, `subtitleFormats`. Config: `maxConcurrentRemuxes`.
- **Tools/tests.** hlssim gains `--mode`, client-profile flags, WebVTT rendition validation, and

## Summary
Server-side remux ("direct stream") in `server/src/Streamarr.Server/Transcoding/`. The planner decides
direct → remux → transcode with stable reason codes. A remux copies the video (HEVC as `hvc1`) into fMP4 HLS on a
keyframe-accurate VOD playlist built from Matroska Cues or the MP4 sample table over range reads (ffprobe scan
fallback, else transcode). Audio is copied or converted (E-AC-3 5.1 → AC-3 5.1 → AAC stereo within
`maxAudioChannels`), and text subtitles become WebVTT renditions. `CODECS` comes from the configuration record,
`VIDEO-RANGE` is PQ/HLG/SDR (Dolby Vision 8/7 as base layer, profile 5 → transcode), and `BANDWIDTH` from index byte
positions. Far seeks restart ffmpeg one keyframe early on the same timeline, with per-run decode times aligned to
the served init. Remuxes use a separate capacity pool (`maxConcurrentRemuxes`). The full-transcode path is
unchanged and remains the default for sessions (`mode` request field). The contract, OpenAPI, web types, admin UI
(mode badge, plan explanation, settings, Playback Preview remux option), hlssim and docs are updated.

  what M1.3's `/switch` should do.
- The ffprobe-scan fallback must read the whole file within 20 s, so large MPEG-TS sources over Usenet fall back
  to a transcode (`keyframe_index_unavailable`).
- WebVTT: ASS styling is reduced to `<b>`/`<i>`. A subtitle segment far from the running copy returns the cues
  known so far rather than blocking (a player that loads subtitles ahead of video may see an empty segment once).
- The `503 remux_capacity` path is covered by shared code with `transcode_capacity`. There is no deterministic
  integration test for it: remux runs finish too fast, and paused runs are reclaimable. Pool separation itself is
  tested.
- Behaviour change: direct-play assessment now uses only the request's `maxHeight`/`maxBitrateKbps`. The server
  transcode caps no longer mark a file as "not direct playable".
- The admin UI preview uses `hls.js/light`, which has no subtitles. The viewer client should use the full build.
- Environment: web tests on the default Node 25 need `NODE_OPTIONS=--no-experimental-webstorage` (jsdom
