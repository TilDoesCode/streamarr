## Summary
Dev World can now break every delivery, API and session path of the player on demand, per playback (or work, viewer,
next start, global), once / always / count, with TTL, listed and cleared over `/devworld/faults` (+ `/devworld/playbacks`).
All 38 spec faults plus `stream_dead` (the spec's H3 hook) are implemented. Nothing under `server/src` changed;
`DEVWORLD_FAULTS=0` registers nothing.

- H1/H2 `DevWorldFaultMiddleware` (between artwork origin and `UseStreamarrServer`): classifies `/transcode/{t}/…`,
  `/stream/{t}`, `/viewer/playback…`, `/viewer/watch/progress`, `/viewer/auth/refresh`, other `/viewer/*`. It learns
  playbackId → work, viewer, method, release, HLS/stream tokens from the start/poll/switch JSON and the segment
  durations from `main.m3u8`. It short-circuits with the product envelope, delays, stalls, aborts, or buffers and
  rewrites the body (truncate, reset, corrupt, VTT, playlists, Content-Type, throttle). For direct play it rewrites
  the Range or wraps the body stream. Every faulted answer carries `X-DevWorld-Fault`, and every hit logs one
  Information line with tokens redacted.
- H3 `FaultPlaybackMedia` (HLS start throws/hangs, probe returns nothing, StreamAlive false), H4 `FaultPlaybackResolver`
  (hang, dead; records stream token → work/viewer for scoping and for `transcode_slow`).
- H5 `tools/ffmpeg-fault.sh` as `Streamarr:Transcoding:FfmpegPath` (copied into `<state>/faults/`, chmod 755). It execs
  the real ffmpeg (`DEVWORLD_FFMPEG`, default from PATH), records `pid → args`, prunes dead pids, and adds `-readrate`
  to the first `-i` of session runs (`-progress`) whose args name a token with a slow file. `transcode_kill` signals
  those pids.
- H6 session store via `IDbContextFactory<StreamarrDbContext>`: `token_expire`, `session_revoke` (public reason →
  stored reason the product maps back), `password_change` (`MustChangePassword`, reset on clear).
- H7 `playback_gone`: closes the HLS session(s) and stream capability, then 404 `playback_not_found` for poll/switch/stop.
- H8 `MockNntpServer.BodyScripts` (430 Missing) / `BodyGates` (held bodies) for the articles of a percent range.
- `DEVWORLD_PLAYBACK_IDLE_SECONDS` → `Streamarr:ViewerPlaybackIdleSeconds` (short idle expiry scenario).

## Decisions
- Smoke script name: the task text says `tools/faults_smoke.py` (the spec § 6.5 calls it `fault_check.py`). I followed
  the task text.
- Boot tests: one boot test arms the API/auth/scope faults over HTTP on FakeWorld (random bytes, no ffmpeg), and a
  second one boots with faults off. There is no per-fault boot test for the media faults: they need real
  media/ffmpeg, so `faults_smoke.py` checks each one live on a fresh Dev World (exact status, code, headers, body
  change, timing). The unit tests cover matcher, targets, scopes, modes, TTL, global, redaction and the body rewrites.
- `probe_fail` returns null from `ProbeAsync` instead of throwing. Null is the port's "ffprobe cannot read it", so the
  server answers its real `probe_failed`; a thrown exception would reach a generic failure path.
- Stream tokens are reused across a viewer's playbacks, so the H3/H4 hooks match by work + viewer (a `playbackId`
  scope compares the bound playback's work and viewer). The last playback of a token is not used for this.
- `next` faults bind to the playbackId of the viewer's first start answer. Before binding, the internal hooks match
  them by viewer.
- State-like faults default to `always` (`playback_gone`, `playback_stuck`, `captive_portal`, both playlist faults,
  `early_end`, `direct_truncate`, `throttle`); all others default to `once`.
- Resets/truncation flush, wait 150 ms, then `HttpContext.Abort()`. Kestrel drops unsent bytes on abort, and the
  client must see the partial body.
- `usenet_hole` on Dev World: the server reads small files ahead completely right after the first read (and probes at
  resolve), so armed after ready it usually changes nothing on direct play. Armed before the start (scope `workId`),
  the server's health check finds the hole: `failed release_dead` with both releases dead (B06). On a larger remux
  (Sintel HEVC, 24 MiB) armed mid-play, reads past the hole answered 500. Documented in the README.
- `transcode_kill`: the product restarts the killed ffmpeg transparently. The following segments were 200 in every
  run (no 500 seen), so the smoke asserts the kill (≥ 1 process signalled) and reports what followed.
- `stream_dead` is extra (spec H3 lists it, § 4 does not): StreamAlive is consulted on switch, so the server re-resolves.
- The smoke leaves server state behind (the health cache marks the hole releases unhealthy for 120 s). Run contract /
  e2e checks on a fresh instance, not right after the smoke.
