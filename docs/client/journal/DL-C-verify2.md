## Code reading only and remaining uncertainty

**C1-24 and C1-26 above are the remaining code/coverage findings. No additional code-only C2 defect is counted.** In particular, the account-isolation repro uses actual AccountStore, AccountsApi, serverResolver and authenticated API clients; it observed the correct two Bearer tokens and no request for a signed-out owner. C2-01/02 describe authorization bookkeeping failures within an owner, not token substitution between owners.

`within()` limits how long JS waits; it does not abort the underlying DELETE. Workers retain a server reference, so operations can outlive the sign-out wait and overlap a new flush. This explains why generation checks matter in C2-02; a real transport-level credential leak or a measured global concurrency violation is **not** claimed. Engine I/O/drain tests here use the frozen fake and explicit rejection/deferred gates, not a new native implementation or a physical disk failure. Removal paths continue honoring exact io+pending retries and native path claims in the passing existing tests.
