# F13n — native subtitle lift (Q2-02 on Google TV, Apple TV, phones)

Status: in-progress (phase 1 done: code, patch, jest; phase 2 = builds and live checks; nothing committed)

Intent: F13 lifted the web player's subtitle cues above the control bar while the overlay shows (Q2-02); the native
engines ignored the overlay's `setSubtitleLift(fraction)`. Implement it in the expo-video patch (ExoPlayer, AVPlayer),
decide libVLC/VLCKit on evidence. Worktree `../streamarr-f13n`, branch `round-i/f13n` at 629d470 (= main + F13).

## Phase 1 — code (2026-10-07, no builds, no devices)

| Part | Change |
|---|---|
| JS contract | unchanged: `player-overlay.tsx` calls `engine.setSubtitleLift(1 − barTop / window.height)` while the controls show, 0 when they hide. The fraction is a share of the **window** (= the full-window VideoView) |
| `expo-video-engine.tsx` | `setSubtitleLift` clamps to 0–1, rounds to 3 decimals and calls the patched native `player.setSubtitleLift(lift)` **only on a change** and **only while a VideoView shows the player** (the Surface reports mount/unmount; a lift set before the view mounts is sent when it mounts). Unpatched build (no native function) or released engine: nothing. The native player keeps the lift across views and items, so a remount with the same lift sends nothing |
| `native-probe.ts` | `NativeProbe.setSubtitleLift?` |
| patch, Android | `VideoModule.kt` `Function("setSubtitleLift") { ref: VideoPlayer, lift: Double }` on the main queue (same pattern as `play`). `VideoPlayer.subtitleLift` (setter applies it to `currentVideoView`; `changeVideoView` applies it to a new view). New `utils/SubtitleLift.kt`: media3's `SubtitleView` sits **inside** `exo_content_frame` (media3-ui 1.9.0 `exo_player_view.xml`), i.e. it covers the picture, not the view — so the bar's share of the view is converted to its share of the picture (`barTop = view.height × (1 − lift) − subtitleView offset`), then `setBottomPaddingFraction(DEFAULT_BOTTOM_PADDING_FRACTION + share)` (0.08 + share, share ≤ 0.8); lift 0 or a bar entirely in the letterbox → the default 0.08. An `OnLayoutChangeListener` on the SubtitleView (once per PlayerView, WeakHashMap, weak view ref) re-places the cues when the picture changes size (aspect known, content fit, rotation) |
| patch, iOS/tvOS | `VideoModule.swift` `Function("setSubtitleLift")` → main queue → `VideoPlayer.subtitleLift` (didSet applies). New `VideoPlayerSubtitleLift.swift`: `applySubtitleLift()` sets the current item's `textStyleRules` to one `AVTextStyleRule` with `kCMTextMarkupAttribute_OrthogonalLinePositionPercentageRelativeToWritingDirection = (1 − share) × 100 − 8`; share 0 → `textStyleRules = nil` (default place). `share` = the bar's share of the **picture** (`playerViewController.videoBounds` of the view showing the player). Re-applied on item change (`onItemChanged`), on a new player for a view, and on every `videoBounds` change (KVO in `VideoView`). `VideoManager.videoViews(of:)` finds the views |
| jest | `FakeExpoPlayer.setSubtitleLift` records lifts (`subtitleLifts`). New `src/player/__tests__/expo-video-subtitle-lift.test.tsx`: waits for a VideoView then sends the latest lift once; only changes reach native, 0 restores; no call for an initial 0 or while unmounted, remount sends the new lift; clamped, nothing after release; an unpatched build does not throw |

### libVLC (Android) / VLCKit (tvOS): unchanged — no runtime API

Evidence (the builds in use: `org.videolan.android:libvlc-all:4.0.0-eap29`, `VLCKit 4.0.0a24`):
- libvlcjni (`libvlcjni.so` JNI symbols, `MediaPlayer`): `SetSpuDelay`, `SetScale`, `SetAspectRatio`, `SetDisplayFit`,
  `SetTeletext*`, `SetVideoTitleDisplay` … — no subtitle margin/position, no generic variable setter.
- libvlc 4 public API (`libvlc.so` exports, VLCKit `vlc/libvlc_media_player.h`): `libvlc_video_set_spu_delay`,
  `libvlc_video_set_spu_text_scale` only; no margin.
- VLCKit `VLCMediaPlayer.h`: `currentVideoSubTitleDelay`, `currentSubTitleFontScale` only.
- The core does have the vout variable `sub-margin` (strings in `libvlc.so`; `var_SetChecked` and
  `vlc_player_vout_HoldAll` are exported), but reaching it needs the private `libvlc_media_player_t` layout (its
  `vlc_player_t`) and, on Android, libvlcjni's private object pointer through reflection — a new NDK library built
  against two private ABIs that change between 4.0 EAP builds. Not done; `--sub-margin` stays a media-open option
  and the brief rules out reloads. vlc-engine.tsx keeps no `setSubtitleLift` (the overlay's optional call is a no-op).
