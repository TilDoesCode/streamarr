# B10 — Server: image sizes per use, tagline only in the viewer language, long-season artwork, alias cooldown

Status: done

## Summary
(1) Every artwork URL on viewer list items and details now has an additive size-class sibling `{small, medium, large}`
(`posterSizes`, `backdropSizes`, `stillSizes`, `seriesPosterSizes`; schema `ArtworkSizesDto`): posters w185/w342/w780,
backdrops and episode stills w300/w780/w1280 (TMDB buckets; any URL in TMDB's `/t/p/{size}/` layout is re-sized, other
URLs are the same in every class). Plain URL fields unchanged; OpenAPI re-frozen (+123 lines, additive), web types
regenerated, client `schema.d.ts` regenerated (no client code touched). A web Home card poster drops from 160 KB (w780)
to 17 KB (small) / 43 KB (medium), a backdrop from 145 KB (w1280) to 15 / 67 KB.
(2) Taglines are only in the viewer language: TMDB's English request still fills a missing overview, never the tagline
(null). (3) Dev World draws generated artwork (SkiaSharp) for The Lighthouse Logs — poster (en/de title), backdrop, 26
episode stills — once into `cache/art/v1/{size}/` in the same size classes, serves it at `/devworld/art/t/p/{size}/…`,
names it by the caller's origin (10.0.2.2 on the emulator) and lists the series in `popular-series`; ids unchanged.
(4) The sign-in code endpoint no longer links aliases: the only 429 is the per-typed-login cooldown (before the account
lookup); another alias of an account inside its mail cooldown/hourly cap answers 202 without a mail, so mail stays at
one code per 30 s and 5 per hour per account.

## Decisions
- Size classes as additive computed siblings of each URL (not a `size` query on an image route: the server has no image
  route, URLs point at TMDB directly). Three classes instead of every TMDB bucket keep the contract small; `large` = the
  default plain field size. Only the official per-type TMDB buckets are used (backdrop w300/w780/w1280, poster
  w185/w342/w780); stills use the backdrop buckets (the plain still is already w1280).
- Computed get-only properties on the DTOs (`PosterSizes => ArtworkSizes.Poster(PosterUrl)`) so every construction
  site (catalog, search, discover, browse, seasons, next-up, nextEpisode) carries them without per-site mapping.
- Cooldown variant: "answer the second alias like a first send without sending" (not per (account, alias) keys, which
  would allow one mail per alias per 30 s). The per-account limit in `ViewerCodeService` is unchanged and silent.
- Tagline: no English fallback at all for a non-English viewer (a missing tagline alone no longer triggers the English
  request either). The Dev World fixture keeps 10 English-only taglines; Lighthouse got an English-only tagline as a
  demonstrable case.
- Dev World artwork: SkiaSharp (already a server dependency) instead of ffmpeg; drawn per size class (not resampled),
  versioned cache dir `art/v<Version>`; an /api JSON body rewrite in the harness (not in the server) makes the URLs
  reachable from every client origin. Palettes stay TMDB-only (no new server knob), so Lighthouse has no tint.
- Lighthouse added to `popularSeries` only (end of the row): the trending rows and other fixture lists are unchanged.
