# B15 — Server: delivery issues in the progress answer

Status: done

Intent: record per playback the delivery failures the server answered or caused on its HLS routes (audio rendition,
subtitle rendition, main stream), last ~60 s, bounded; expose them as additive `deliveryIssues` on the
POST /viewer/watch/progress answer and the GET playback status; the Dev World fault layer reports its synthetic answers
through the same product hook. Builds on the uncommitted B14 tree. Test tree on Dev World 39310 only.

## Summary
Per playback the server now records the error answers of its current HLS session (kind, renditionId / subtitle stream
index, code, status, at; equal issues collapse to the latest; ≤ 16 entries, 60 s, dropped with the playback, cleared on
switch). `POST /viewer/watch/progress` with a live playbackId answers `deliveryIssues` = issues recorded since that
playback's previous progress answer, at most 30 s old (each told once; `[]` none, `null` without a live id);
`GET /viewer/playback/{id}` lists the last 30 s (not consumed). Fault-layer answers (seg_status, rendition_status,
subtitle_status, seg_stall respond, early_end, split_abort) go through the same hook. OpenAPI re-frozen (additive),
docs/api.md + Dev World README, web + client types regenerated.

## Decisions
- Window: "since the previous progress answer of the same playback, at most 30 s" (sequence-based, so nothing is told
  twice or lost at equal timestamps); the GET status is the non-consuming last-30-s view for polls and debugging.
- The route carries the HLS session capability, not the playbackId: a session belongs to exactly one playback, so the
  sink maps session → playback (current session only). Lookup scans ≤ 1024 playbacks only on error answers.
- Status 500 for an answer that broke off after it started (the client saw a reset), code from the failure.
- Network-style Dev World faults (seg_reset, seg_truncate, seg_corrupt, delays) are not recorded: the server would not
  know about them in production either. 2xx/3xx never recorded; codes bounded to 64 chars; no token material stored
  (only the rendition id / subtitle index, code, status, time).
- Types were regenerated twice in this turn (once before the required→optional change); the final files match the
  final spec.
