## Summary
- **Core TMDB.** `TmdbDiscoverQuery(MediaType, GenreId?, Sort, Page)`, `TmdbDiscoverPage(Items, Page, TotalPages,
  TotalResults)`, `TmdbGenre(Id, Name)`, `TmdbDiscoverSort { Popular, TopRated, Newest }` (new `Tmdb/TmdbDiscover.cs`).
  `ITmdbClient.DiscoverAsync` / `GetGenresAsync` (empty defaults). `TmdbClient`: `discover/movie|tv?include_adult=false&
  include_video=false&page=N` + `sort_by=popularity.desc` | `vote_average.desc&vote_count.gte=300 (tv 200)` |
  `primary_release_date|first_air_date.desc&…lte=<today>&vote_count.gte=10`, `with_genres=G`; `total_pages` capped at 500;
  `genre/movie|tv/list`. `CachingTmdbClient`: discover cached per (type, genre, sort, page) for the list TTL
  (`Tmdb:DiscoverCacheTtlHours`, 6 h, like the home rows), genres for the full TTL (`Tmdb:CacheTtlHours`, 24 h); strict view too.
- **Endpoints.** `GET /api/v1/viewer/catalog/browse?type=movie|series(|tv)&genre&sort=popular|top_rated|newest&page` →
  `CatalogBrowseResponse { mediaType, genre, sort, page, totalPages, hasMore, items: CatalogItemDto[] }` (items with
  tint/tint2/spec via the shared `Item` mapper, age gate via the shared `AllowedAsync` exactly like discover/search, 503
  `catalog_unavailable` on outage or when every certification lookup failed). `GET …/genres?type=` →
  `CatalogGenresResponse { mediaType, genres: [{ id, name }] }`. Validation: `400 invalid_query` for missing/unknown type,
  genre ≤ 0, unknown sort, page outside 1–500; non-numeric values `400 invalid_request` (model-state filter).
- **Dev World.** `CannedTmdbClient.DiscoverAsync` / `GetGenresAsync`: genre names → TMDB ids (standard table), genre list =
  genres the fixture titles of that type have, popular = popular row then trending row then rest, top_rated by
  communityRating, newest by year, **4 per page** (9 movies → 3 pages). Cards only (no certification), like real lists.
- **title_not_found.** Catalog problems during a playback now suggest only what can help (`ViewerPlaybackService.ProblemActions`):
  404 (`title_not_found`, `season_not_found`, `episode_not_found`) and 403 `age_restricted` → none; 429/503 → `retry`; other → `otherVersion`.
  Other codes reviewed: `useVlc` is no longer suggested once VLC direct is in the step-down exclusions (decider `Failure` and
  the start-failure path). The rest (`no_versions` retry, `release_*` otherVersion, capacity retry…) are sensible; unchanged.
- **Prediction container.** `PlaybackPredictor.Source` assumed MKV unless the name contains "MP4". New `ReleaseContainerStore`
  (singleton, in memory, max 20 000): records the probed container of every viewer playback (`probe.Container`) and falls back
  to live stream sessions (`ActiveSession.File.Container`, from the file extension; also covers Jellyfin resolves).
  `Predict`/`Classify` take `knownContainer`; with it the `container_assumed` note disappears and the container is real.
  Live: BBB WEB-DL on Chrome hints was `remux` (container_assumed) → playback `direct/web` → versions now `direct`, recommended.

## Decisions
- `hasMore = page < totalPages` from TMDB; the age gate may leave a page short or empty — clients page on `hasMore`
  (documented). No server-side refill across pages (would break stable page numbers).
- Genre ids are TMDB's; names come in the server's TMDB language. `type` accepts `tv` as alias like search.
- Container knowledge is in memory only (no migration): a restart forgets it until the next playback/session. Before a
  release was ever opened there is no way to know it without fetching the NZB, so the name heuristic stays for that case.
- Dev World genre list only lists genres present in the fixtures, so no genre page is empty.
