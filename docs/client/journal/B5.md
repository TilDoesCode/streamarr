# B5 - Server: multi-rendition audio in HLS

Status: done

## Summary
Remux and transcode deliveries with two or more offered audio tracks now carry them as HLS audio renditions of one
group (`EXT-X-MEDIA:TYPE=AUDIO,GROUP-ID="audio"` with NAME, LANGUAGE, DEFAULT, AUTOSELECT, CHANNELS; variant
`AUDIO="audio"`), so players switch language inside the session. One ffmpeg process still writes one muxed fMP4
(video + up to 4 audio tracks, each copied or converted per the device profile); the server serves video-only and
per-rendition segments by splitting each fragment per track (`Fmp4TrackSplit`), so all renditions share the segment
boundaries and the restart/seek logic. The playback response lists `audioRenditions` (id, streamIndex, language,
label, channels, codec, default) and `inSessionAudioSwitch`; audio tracks carry `renditionId`. `/switch`, seek,
resume, stop, heartbeats and WebVTT subtitles are unchanged. hlssim, e2e and the contract check validate the
renditions; docs, OpenAPI, web and client types updated.

Intent: remux and transcode deliveries carry the offered audio tracks as EXT-X-MEDIA TYPE=AUDIO renditions (one group),
so players switch audio in-session; playback response lists renditions + inSessionAudioSwitch; docs, contract, e2e.
Slice 1 started 2026-10-01 17:19 (design + remux master/rendition playlists).

## Decisions (slice 1)
- **One ffmpeg process, server-side demux.** The session keeps producing one muxed fMP4 (remux: stdout -> RemuxSegmenter;
  transcode: hls muxer) with the video plus every offered audio track (video = track 1, rendition i = track i+2).
  `Fmp4TrackSplit` serves per-track init/segments on request (moof reduced to the track's traf, trun data offsets
  rewritten, default-base-is-moof). Video and audio renditions therefore share the segment timeline and boundaries by
  construction (no var_stream_map: it would replace M1.4's keyframe-accurate remux segmenter and its restart logic).
- Renditions only when >= 2 audio tracks are offered; a single track stays muxed exactly as before (no change for
  existing clients/tests). Offer = selected track, then preferred language, source default, other languages; one
  track per language; max 4 (`TranscodePlanner.MaxAudioRenditions`). Direct play/VLC: none (engine switches locally).
- Each rendition is planned like the single track today (remux: copy if the device decodes it else E-AC-3/AC-3/AAC
  fallback within maxAudioChannels; transcode: AAC). Converted remux renditions keep their own atrim origin.
- Routes: `audio/{id}/main.m3u8|init.mp4|{n}.m4s` next to the master (id = source stream index); `main.m3u8`,
  `init.mp4`, `{n}.m4s` become video-only when demuxed. Master: `EXT-X-MEDIA:TYPE=AUDIO,GROUP-ID="audio"` with NAME,
  LANGUAGE (BCP-47), DEFAULT, AUTOSELECT=YES, CHANNELS; variant `AUDIO="audio"`, CODECS lists every audio codec,
  BANDWIDTH adds the largest rendition's extra bitrate.
- Contract: `PlaybackResponse.inSessionAudioSwitch`, `audioRenditions[]` (id, streamIndex, language, label, channels,
  codec, default), `mediaInfo.audioTracks[].renditionId`.
