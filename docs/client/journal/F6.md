## Decisions
- Edge to edge on iPhone via NativeTabs `disableAutomaticContentInsets` on the Home tab only (root cause), not by
  fighting the inset in Home; Search/Settings keep UIKit's automatic inset (large titles).
- Status-bar scrim lives inside the Home ScrollView as a sticky header: any wrapper view in front of the ScrollView
  breaks UIKit's adoption (tab-bar minimise). Shared `StatusBarScrim` also used by the phone detail.
- One `BackControl` (navigation/back-control.tsx): drawn where no native back exists (large shell incl. iPad/web/
  tablet, Android and web phones); hidden on TV and iPhone (native Liquid Glass back). Floating top-leading, below
  safe area + iPadOS window controls, `useBackControlClearance` pushes the copy below it. First in the DOM on web.
  Escape/Alt+Left not added (browser Back already works on web; time).
- The Versions side panel/sheet gets a close X on touch/pointer (not TV) instead of a back arrow: it is an overlay.
- No Android tablet AVD exists; tablet width checked on web 820 px (same `shell.large` code path as iPad/tablet).
- No native rebuild (JS only).
- Slice 2: one clearance rule in `theme/focus-clearance.ts` (growth per side + ring x scale + air), tokens `focus.air`
  and `focus.buttonExtent`; buttons wider than the extent lift less (same per-side growth) instead of growing the row
  gap with the label; rows only ever get their gap raised (`useFocusGap`), so phone/web layouts keep their spacing
  where it was already enough. Card rows: 40 pt on TV only (`useCardGap`); web keeps 24 pt (7 grid columns at 1280).
- TV air = 8 units (16 dp on Apple TV): 4 units still read as touching on the 4K simulator (first pass).
- Failed player start on TV draws no corner X (the card always offers Zurück, Menu closes); with it the actions were
  unreachable. No unit test: the play screen has no test harness; verified live (38 -> 39).
- Web BackControl Enter: works (native button); no code change.
