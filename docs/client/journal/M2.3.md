Status: done (fix round 1: the blocking finding and non-blocking 1–7 fixed and re-verified on web + Google TV; carried-over web Back stays with M2.4; pending-ios: Xcode not installed, iOS/iPadOS/tvOS not built or run)

## Intent
Typed `openapi-fetch` client per account/server generated from `server/openapi/v1.json`
(`npm run gen:api`), auth middleware with single-flight refresh rotation
(`refresh_token_reused` / failed refresh → that account is signed out), error envelope →
typed `AppError` with an i18n entry for every documented viewer error code. Account store
(expo-secure-store native, localStorage web) for several accounts on several servers.
Screens: server connect (URL normalisation, probe `/api/v1/viewer/auth/options`, messages for
unreachable / TLS / module_disabled / not a Streamarr server, plain-http warning outside private
networks), sign in (password, email code, forgot/reset password, second factor + recovery
code, must-change-password), "who's watching?" picker, add/switch/sign out/remove.
React Query with per-account key partitioning, cache reset on switch, AppState/NetInfo
managers, MMKV-persisted home rows per account. Verify against the Dev World snapshot
(39300) on web (Chromium via Argent) and Google TV (tv-remote); unit tests for middleware,
account store, error mapping.

## Summary
Data layer, auth and multi-account for the viewer client.
- **API** (`src/api`): `openapi-fetch` typed from the generated `schema.d.ts` (`npm run gen:api`, unchanged
  output). `createApiClient({ baseUrl, session })` → one client per account/server with an auth middleware:
  bearer token, proactive refresh 30 s before expiry, on 401 a single shared refresh per account
  (`AccountSession`, single flight; re-reads the vault first so another browser tab's rotation is adopted instead
  of replaying an old refresh token), one replay of the original request (an unread clone, rebuilt as a standard
  `Response` because RN's global fetch is expo/fetch), `refresh_token_reused` / `refresh_session_expired` (any 401
  from refresh) sign the account out, network/5xx failures keep the session. `403 password_change_required` flags
  the account. `unwrap()` turns every failure into `AppError { code, status, params, retryAfter }`; transport
  errors are classified (`network_unreachable`, `timeout`, `tls_error`, `aborted`), 20 s request timeout.
- **Errors + i18n**: `error-codes.ts` lists every documented viewer code (auth, /me, catalog, watch, playback
  requests, failed-playback codes) plus client codes (`not_streamarr`, `invalid_url`, `tls_error`,
  `mixed_content`, `session_ended`, …); en/de title + message for each (typed keys → tsc fails on a missing en
  key; parity test for de). `describeError()` adds the age-gate reason (ICU select) and the other device of
  `too_many_streams`. A test scans `docs/api.md` §12–13 + `docs/viewers.md` so a newly documented code must be
  added.
- **Server connect** (`server-url.ts`, `probe.ts`): own URL parser (RN's URL polyfill neither validates nor
  handles IPv6), strips pasted API paths, keeps reverse-proxy base paths, no scheme → http first on private
  hosts, https first (http fallback) on public ones; probes `GET /api/v1/viewer/auth/options` over XHR (keeps the
  native error text for TLS detection), reports the most specific failure; `insecure` = plain http outside
  private ranges (RFC 1918, loopback, link-local, CGNAT/Tailscale, ULA, `.local`/`.lan`/…, single-label).
- **Accounts** (`src/accounts`): `AccountStore` (list + active id in MMKV `streamarr.accounts`, web localStorage;
  tokens in the vault: expo-secure-store with `AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY` on native, localStorage on
  web), several accounts on several servers deduplicated by (server URL, viewer id), distinct avatar colour slot,
  sign out keeps the profile ("Signed out" / the end reason), remove forgets it and its persisted cache.
  `createAccountsApi` (activate = cancel + clear the query cache, sign out/remove end the server session best
  effort, re-sign-in ends the replaced session), `AccountsProvider` + hooks (`useAccounts`, `useSessionGate`,
  `useActiveAccount`), `useProfileSync` (`/viewer/me` every 5 min: display name, forced password change, session
  check). "Who's watching?" is asked at launch when more than one profile is signed in (web: per tab).
- **React Query** (`src/query`): retries only transient failures (network, 5xx, 429 with Retry-After), focus via
  AppState and online via NetInfo on native (browser events on web), stale times (default 1 min, profile 5 min,
  home rows 30 min, server options 1 min), keys `['account', id, …]`, home rows persisted per account with
  `experimental_createQueryPersister` in MMKV `streamarr.cache.<id>` (7 days, buster = app version + cache version).
- **Screens** (all de/en, loading/error/disabled states): `/server` (known servers, validation, errors, insecure
  warning), `/sign-in` (password, links to email code / forgot password / change server, reason banner after a
  session end), `/sign-in/second-factor` (6 digits or recovery code, expiry → start over), `/sign-in/email-code` +

## Decisions
- **Web tokens in localStorage, not the cookie mode**: the viewer cookies are `SameSite=Strict`, scoped to the
  server origin and one per browser, so a cross-origin web app (and the Dev World's `Access-Control-Allow-Origin:
  *` without credentials) cannot use them, and one cookie jar cannot hold several sessions on one server
  (multi-account). Risk accepted: XSS could read tokens; mitigated by opaque, rotating, revocable tokens.
- **A failed refresh signs out only when the server rejects it (401)**; offline or 5xx keeps the session (a flaky
  network must not sign people out). `module_disabled` during refresh keeps the session too.
- **Profile picker at launch** only with ≥ 2 signed-in profiles; one profile goes straight home.
- **Sign out keeps the profile** (tile shows why it was signed out); remove is a separate, confirmed action.
- **Explicit redirects in `(app)/_layout`** instead of `Stack.Protected`: deterministic targets per gate reason.
  Onboarding routes live in `(onboarding)` without their own layout (flat root stack); leaving onboarding does
  `dismissAll()` + `replace('/')`, so Back on TV/Android exits from home.
- **Secrets never in route params**: server URL, login and end reason are params (reload-safe on web); the MFA
  token and the typed password (for the forced change) stay in memory (`signInFlow`).
- **Server probe over XHR** (native error text for TLS detection); normal API calls over fetch.
- **Per-query persistence** (only home rows) rather than persisting the whole client: no stale detail data, no
  cross-account restore; one MMKV instance per account so removal is one `deleteMMKV`.
- **Dev hook** `globalThis.__streamarr` (dev builds only) so Argent's `debugger-evaluate` can inspect accounts,
  the query cache and call `clientFor` on devices.
- `expo-secure-store` config plugin with Android backup rules (Keystore keys do not survive a restore) and
  `faceIDPermission: false` (no biometrics used).

### Non-blocking
1. **TV forms: a field can end up at the very top edge, with its label off-screen.** On sign-in, Down to "Change server"
   scrolls the form up about 45 dp. When you go back Up to "Username or email", the view does not scroll back. The focused
   field then sits flush against the top edge, inside the overscan band, and its label is hidden
   (`googletv-verify2-sign-in-change-server-focused.png` → `googletv-verify2-sign-in-login-field-at-top-edge.png`). The
   field still works. Fix: snap the form back to the top when the first field gets focus, or keep a top inset.
2. **A refresh that finishes after a sign-out writes its tokens back into the vault.** I reproduced this on the device
   through `debugger-evaluate`. I held the refresh response for 1.5 s after the server had answered 200, and signed the
   account out in that window. The store showed `signedIn:false`, yet `readTokens(id, true)` still returned the rotated pair.
   The server side is fine: the logout with the old refresh token ended the session, and the rotated access token gets 401.
   So only dead tokens stay on the device, and the next sign-in replaces them. Fix: in `AccountSession.rotate()`, drop the
   refresh result when the account is no longer signed in (or its vault entry is gone) instead of calling `writeTokens`.
3. **The 2FA code fields are plain text inputs** (TOTP `0x80002`, recovery code `0x80001`). Gboard on the emulator
   suggested `ben-recovery-01` in the login field, so at some earlier point a recovery code was learned by the keyboard. It
   is a one-time code, so the risk is low. Consider `visible-password` for the recovery code on Android, as for shown
   passwords.
4. **Some failed-playback codes have no specific text.** The server's playback failure takes `lastError?.Code` from the
   HLS start (`ViewerPlaybackService`), so codes such as `too_many_sessions`, `remux_not_possible`, `ffmpeg_unavailable`,
   `transcoding_disabled` or `insufficient_disk` can reach `error.code`. `docs/api.md` only says "a transcode start code
   (`segment_timeout`, `transcode_failed` …)", so the docs scan cannot see these codes, and they show the generic text.
   This is a job for M4.2, or the backend should document the full list.
5. **German TV profile dialog:** "Anmelden" and "Von diesem Gerät entfernen" fill the first row, so "Abbrechen" wraps onto a
   row of its own (`googletv-verify2-german-profile-dialog-wrapped.png`). D-pad still works: focus starts on Abbrechen and
   Up goes to Entfernen.
6. **Trivia:** about 40 exports are only used inside their own file or by tests (for example `initials`, `avatarColor`,
   `ServerChip`, `useHomeRows`, `REQUEST_TIMEOUT_MS`, `AVATAR_COLORS`). They are not dead code, but they widen the modules'
   surface. On Google TV, Argent `describe` worked this round (source `tv-focus`) and failed only twice ("uiautomator …
   Killed") right after a relaunch.
