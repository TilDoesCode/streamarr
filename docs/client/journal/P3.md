## Summary
- **Watch state:** once a playback crosses the played threshold, later reports of the *same* `playbackId` (late/out-of-order
  progress, seeking back in the credits, a `stop` below the threshold) no longer revive a resume position, so the work leaves
  continue watching, series `nextEpisode` stops saying "resume" and next up advances. A rewatch (new `playbackId`) of a played
  work keeps `played` and its resume point, and playback start now returns that `resumePositionTicks` (it was dropped for
  played works, which is why the client showed "1 min left" and started at 0).
- **One probe per start:** viewer playback serves the resolve-time ffprobe from the transcoder's full probe (one ffprobe run,
  JSON parsed into both models, cached for the plan). Cold start median 1030 → 532 ms on the Dev World.
- **Device-aware "Recommended"** (decision 1): with a device profile the versions list is ordered by what plays without a
  server transcode (highest resolution first, direct > remux > VLC, then quality/health), then transcodes, unplayable last and
  never recommended; `rank`/`recommended` follow that order, new `qualityRank` keeps the pure quality order. A plain "Play"
  uses the same pick with the playback's full device profile and preferences. New `vlcAvailable` query flag; `predictedMethod`
  says `vlc` only when it is sent.
- **Viewer web app under `/watch`** (decision 2): `Streamarr:ViewerWebPath` (default `<content root>/viewer-web`, inert when
  it has no `index.html`), SPA fallback, immutable caching for `_expo/`/`assets/`, `no-cache` for the shell, own CSP
  (TMDB images, blob media/workers, `frame-ancestors 'none'`), Dockerfile `viewer-web` stage (`npm ci` + `expo export
  --platform web` with `EXPO_BASE_URL=/watch`), docs.

## Decisions
- Played + late reports: the rule is "reports of the playback that completed the work (`CountedPlaybackId`) never set a
  position". Reports without `playbackId` keep the old behaviour (no way to tell them apart). Seeking back during the credits
  of the completing playback therefore keeps no resume point (Jellyfin-like).
- Probe merge via an `IResolveProbe` observer hook (AsyncLocal in `ResolveService`, set only for the viewer's resolve) instead
  of threading a parameter through ten resolve overloads; Jellyfin/admin resolves keep the fast two-stage ffprobe. The full
  probe's JSON is a superset of the resolve's `-show_entries`, so `FfprobeClient.Parse` reads it unchanged and
  `MediaProbeCache` stores the same model.
- Device-aware ranking reuses the real `PlaybackDecider` on the name-built media model of `PlaybackPredictor`, so the badge and
  "Play" come from the same rules as playback. "Same quality" = same resolution (parsed height). Compact query hints are turned
  into a `DeviceCaps` (native engine + `DefaultVlc` when `vlcAvailable=true`); `maxHeight` acts as a per-codec device limit.
- `rank` keeps its meaning "position in the default order" (so `recommended == rank 1` still holds); `qualityRank` is additive
  and optional in the schema (always sent).
- `/watch` is mapped before the management SPA, auth and routing; the management SPA fallback excludes `watch`. Without the
  folder `/watch` answers like any unknown path (401 from the fallback policy).
- #4 multi-rendition HLS audio: not implemented (design note below), the rest took priority and it is a remux redesign.

## Design note — multi-rendition HLS audio (#4, not implemented)
Remux today muxes one audio track into the fMP4 segments; audio switches go through `/switch` (0.3-1.1 s). For client-side
switching: keep the video-only fMP4 media playlist, add one `EXT-X-MEDIA TYPE=AUDIO,GROUP-ID="aud"` rendition per audio track
(`LANGUAGE`, `NAME`, `DEFAULT`, `AUTOSELECT`, `CHANNELS`), each its own audio-only fMP4 playlist cut on the same segment
boundaries (the keyframe index already gives them). Per track: copy when the device takes the codec, else convert (AAC stereo /
EAC3 5.1); spawn ffmpeg per rendition lazily on the first playlist request, with the same restart-on-seek logic per rendition
and a shared `-output_ts_offset`. Costs: one extra ffmpeg per active audio track, disk per rendition, and alignment tests
(hls.js + AVPlayer). The playback API would report `deliveredAs: rendition` so the client switches in the engine.
