## Summary
Server backlog sweep from the round I verifiers. Refresh rate limit (per IP 60/min, per presented token 10/min,
429 rate_limited + Retry-After, aggregated refusal/limiter log lines, request-log 429 at Debug); superseded starts are
cancelled by switch/stop and never register a session or take a slot; account deletion under the session lock,
IsDisabled on replay, tombstone lookup before the retired-hash scan; four of five flaky tests deterministic (20/20 under
load), the fifth (RepairConcurrency) has one timing cause fixed and a remaining product race documented; tests for the
WebVTT wait cap, the budget across restarts and the segment_evicted response; Dev World nits; docs. Found the real cause
of the B13b late session: Process.Start blocks on macOS while any ffmpeg is throttle-paused (BACKLOG, high).

## Decisions
- Refresh limiter in the controller (token is in the body/cookie, the ASP.NET limiter middleware runs before binding);
  own fixed-window counters on TimeProvider so tests are deterministic. Limits are options (setup.md). Only Unknown
  refusals are aggregated: refusals of real sessions stay one line each (bounded by real tokens x per-token limit).
- OpenAPI: the 429 is documented on refresh (additive, +20 lines); web + client types regenerated once.
- Superseded start: the run token is linked into the start token (B13b had kept them apart so late sessions "complete
  and close"); a start that still completes is closed at once by the revision check (test kept with a fake that ignores
  the token). The Process.Start/SIGSTOP root cause is not fixed here (core transcoding change, needs Linux check).
- `segment_evicted`: the response is extracted and unit-tested; provoking the open race stays live-only.
- Spent Dev World faults leave the list but stay readable/deletable by id (last 50); faults whose removal undoes an
  effect (password_change, usenet_hole/stall, transcode_slow) stay listed until TTL/clear.
- transcode_kill smoke: the product answers 500 transcode_failed only to a request that is waiting when the run dies;
  the smoke now asks for the first unwritten segment and accepts 500-then-200 or an immediate 200, with restarts + 1.
