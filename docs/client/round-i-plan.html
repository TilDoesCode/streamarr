Runde I – „tip top“

Dein Auftrag vom 4. Oktober, 16:10: weitermachen, bis die App tip top ist. Ziel: Auf jedem Gerät wirkt die App fertig. In den Hauptabläufen bleibt kein bekannter Fehler, nirgends eine optische Unsauberkeit. Die nativen Lücken auf Apple TV sind geschlossen, Release-Builds sind geprüft. Was übrig bleibt, geht nur auf echter Hardware, und dafür steht der Grund dabei. Gestartet um 16:17.

Jede Bau-Aufgabe: bauen → unabhängige Prüfung → bei Bedarf Korrektur → Commit. Gleichzeitig läuft immer nur ein Simulator oder Emulator (8 GB RAM). Es sind nur noch rund 14 GB Platte frei, deshalb wird vor nativen Builds der Platz geprüft.

Die Aufgaben

Q1 · Rundgang Prüfung

Keine Code-Änderungen. Ergebnis ist eine Befundliste mit Schweregrad, Schritten zum Nachstellen und Bild.

  • Teil 1: Web (1280, 1920, 390 px, Deutsch und Englisch), Google TV, Android-Handy
  • Teil 2: iPhone, iPad (hoch und quer), Apple TV, kurz Mobile Safari
  • Abläufe: Anmelden (auch falsches Passwort, Server nicht erreichbar), Profile (anna, ben mit 2FA, Kind), Start, Stöbern, Suche, Detail/Bühne, Blätter, Player (Ton, Untertitel, nächste Folge, Ende, Wiederholen), Einstellungen, Sprachwechsel, Fehler- und Leerzustände, Zurück-Ketten, Fokus

B8 · Server Server

  • Wiederholen behält den Fortsetzungspunkt (Ursache liegt im Server)
  • Gleicher Ton-Codec beim Start und nach einem Wechsel; ehrliche Kanal-Angaben (Sintel 5.1 hieß „2.0“)
  • Kein englisches „Unknown device“ mehr in deutschen Gerätelisten
  • Ein Anzeigename nur aus Leerzeichen wird abgelehnt
  • Kleinkram aus B7
  • Dev World bekommt eine Staffel mit 24+ Folgen, damit die lange Folgenleiste live prüfbar ist

T1 · Tests & Code-Pflege Client

  • Fehlende Tests aus F5 (Rückfall bei Fehlern, Spur-Zuordnung), mit Gegenprobe: Ein Test muss rot werden, wenn der Code kaputt ist
  • Toter Code, doppelte Werte, mehrzeilige Kommentare
  • Ein Test prüft, dass Deutsch und Englisch dieselben Schlüssel haben und keine Texte fest im Code stehen
  • Web: Zwei offene Tabs überschreiben sich nicht mehr gegenseitig das Profil
  • App-Icon und Top-Shelf-Bilder werden kleiner, ohne dass sich das Aussehen ändert

F8 · TV-Feinschliff Client

  • wichtig Warum fliegt anna auf Google TV zwischen zwei Läufen raus? Möglicher Grund: Wird die App mitten in einer Token-Erneuerung beendet, meldet der Server das als Missbrauch und meldet ab. Das würde echte Nutzer treffen.
  • Der Hauptknopf bleibt stehen, solange die Versionen laden, damit der Fokus nicht springt
  • Fokus pro Seite merken, Lücke Genre ↔ Sortierung, abgeschnittene „Folge“-Nummer
  • Lange Staffel live prüfen
  • Die TV-Befunde aus Q1

I4 · Apple TV nativ Client

  • Die Blätter öffnen mit Fokus im Blatt
  • Menü geht genau eine Ebene zurück (Blatt, Raster-Chips, andere Tabs zuerst zu „Start“)
  • Player: Nach Menü behält kein versteckter Knopf den Fokus
  • Einstellungen rutschen nicht unter die Tab-Leiste; kein abgeschnittenes Leuchten
  • tvOS-Build neu; VLC auf tvOS einmal prüfen

F9 · Handy, Tablet, Web Client

  • Web: Esc und Alt+← für Zurück
  • Safari: Vollbild nach dem Schließen, Pause-Anzeige, erzwungene Untertitel
  • iOS: Tab-Namen nach dem Sprachwechsel, große Titel, Querformat nach dem Player
  • Android-Handy: „Anmelden“ halb unter der Tastatur
  • Die Befunde aus Q1

R1 · Release-Builds Client

  • Android TV und Handy, iOS, tvOS, Web jeweils als Release bauen
  • Messen: Startzeit, Speicher, Seitenwechsel auf Google TV (im Dev-Build ~5 s), erstes Bild, Bundle-Größe
  • Klären, ob die Abstürze und Hänger nur im Dev-Build auftreten

Q2 · Abschluss Prüfung

  • Dieselbe Liste wie in Q1 auf allen Geräten, jeder Q1-Befund wird nachgeprüft
  • Fertig ist die Runde, wenn auf keinem Gerät ein P1 oder P2 offen ist
  • Danach kommt der Bericht für Runde I

Schweregrade

StufeBedeutungUmgang
P1Ablauf kaputt, Absturz, Datenverlust, Sicherheit, Abmeldung ohne Grundwird behoben
P2Sichtbarer Fehler: Layout bricht, Text abgeschnitten oder falsche Sprache, Fokus verloren, falscher Zustand, Fokusring berührt einen Nachbarnwird behoben
P3Feinschliff: Abstände, Ausrichtung, Bewegung, Tonfall der Textewird behoben, wenn es billig ist, sonst Backlog

Was ich selbst entschieden habe

  • Wiederholen am Ende: Der Server zählt einen Bericht derselben Wiedergabe, die nach dem Ende wieder am Anfang steht, als neues Ansehen. Der Fortsetzungspunkt bleibt, und „gesehen“ bleibt gesetzt.
  • Echte Hardware bleibt außen vor (Bild-im-Bild, AirPlay, HDR-Ausgabe, Passthrough, Siri-Remote-Touchfläche). Das testest du danach selbst.
